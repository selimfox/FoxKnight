# 庭院原生像素模块 · 接入规格卡

状态：**已绘制主体，待 Coding 接入三关和 Art 实机复核**。此批是对当前细碎且重复的地砖/墙表现的替换候选；静态样张不能证明最终画面已达到创作者的审美标准。不得把 `courtyard_module_assembly_preview.png` 当作整张背景导入。

## 依据与制作边界

- 当前 GDD v0.1 的视觉约束：暗黑幻想、俯视角、像素美术，狐狸／敌人／双刀型瞄准信息优先于地面纹理。场景美术只改变视觉，不改变碰撞、寻路、斩击或浅水的纯视觉性质。
- 创作者给出的《赛菲利亚》截图只作为“统一像素网格、成组色块、可读的墙体厚度”分析参考，不复制其场景、图案或角色；项目已有来源记录见本目录 `README.md`。庭院概念图只作冷月光与暖边缘光的氛围参考，不作为像素输入。
- `pixel_stone_forms.py`、`pixel_water_edge_forms.py` 在原生 16 像素网格上逐点/线/封闭色块绘制；`build_courtyard_pixel_modules.py` 组合与校验图集。没有输入整张高清图、AI 图或第三方纹理，也不通过缩小滤镜制造“像素感”。PNG `_source` 可在像素工具中逐像素改；重新运行生成器会覆盖手工编辑，默认拒绝覆盖，只有明确传 `--force` 才重建精确命名的产物。

## 统一规格

| 项目 | 规格 |
| --- | --- |
| 最小源格 | 16×16 RGBA；按 2× 最近邻导出成 32×32 世界像素 TileSet 格 |
| 完整模块 | 3×3 源格，即 48×48 原生 / 96×96 世界像素；地面和墙模块应完整组合摆放，不以单格随机洗牌破坏石缝连续性 |
| 图层与透明度 | 地面、墙完全不透明；浅水、倒影遮罩、边缘装饰仅 0/255 alpha。动态灯光、反射与波纹由独立系统负责，不烘焙在模块里 |
| 显示 | 关闭纹理过滤与 mipmap，保持整数像素比例；接入后在当前 960×540 游戏视口及原生 1× / 世界 2× 分别检查 |
| 角色关系 | 中央战斗区优先安静石板；裂板、潮湿石板、苔藓和碎石以场边为主，不与瞄准圈、角色剪影争夺注意 |

## 精确图集坐标

坐标均以 Godot `TileSetAtlasSource` 的 **32×32 世界像素格**为单位，左上角是 `(0,0)`。每个 3×3 模块的九个 tile 分别占 `(ox + dx, oy + dy)`，其中 `dx,dy ∈ {0,1,2}`。例如安静石板模块的右下格为 `(2,2)`；把一个模块摆进地图时，应按原来九格的相对位置连续摆放。

目前三关仍引用旧 TileSet/source；新增 source 编号只是便于 Coding 接入的建议，不是已完成场景接入。**当前一格厚墙优先用 `wall_border` 原位换图**；`wall_macro` 是日后真正把墙做成三格厚时的候选，不能硬接进现有闭环。旧地砖/水格曾有其他扩展格，替换时需核对各关原有格位和实时倒影脚本，不可仅替换贴图而保留错误坐标。正式接入、资源过滤、碰撞回归由 Coding 负责。

## 地编组合建议与待验收点

1. 中央主要可走区以两种安静模块交错构成较大的冷色面；每三到五个完整模块才放一个较有纹理的石板 A/B，避免高光重复成为“棋盘线”。破损和湿石只沿墙脚、浅水外缘少量出现。石块边沿有意形成接缝，但不应出现每 96 世界像素一次的整齐、连续横线；若实机仍看到它，Art 应修模块边界而不是靠额外光效遮盖。
2. 当前三关保留一格厚 Walls 闭环时，用 `wall_border` 的十二个格位原位替图；不可把 3×3 墙宏块的一行直接塞进闭环。以后关卡确有三格厚墙段时，才把 `wall_macro` 的顶盖、立面和墙脚按三行完整叠放。火盆亮度由独立动态火焰控制，墙贴图不包含火焰或烘焙光池。墙角形状、碰撞层和遮挡关系仍需在真实场景里校核。
3. 第一关左上浅水先摆一个 3×3；独立 mask 跟随格位同位。水仅是材质，进入后现有实时倒影／轻波纹按脚底与当前角色帧处理；若要扩大池面，先补可编辑边缘模块，不把整张水截图伸缩到关卡。
4. 在实际游戏尺寸逐关看 3 个位置：中央是否抢角色剪影、左上浅水是否有动态倒影、墙脚与火焰是否接地连续。还需测试玩家移动、瞄准、斩击和三关不同地编，不以本目录预览作为通过依据。

`courtyard_module_assembly_preview.png` 是排布样例，仅用于检查 2× 最近邻像素、低频明暗和模块重复节奏。正式资源是上述六组成对的 `_source.png` 与 `.png`；玩家可在图块编辑器按 32 世界像素格重新编排。
