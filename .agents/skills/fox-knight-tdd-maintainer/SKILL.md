# 狐狸骑士 TDD 维护

## 守住职责边界

- 作为 Coding Agent 的技术文档维护流程工作，不替代 Architecture Agent 决定玩法、范围或 GDD 版本。
- 始终以 `docs/GDD.md` 的当前已确认内容为设计边界；代码现状和 TDD 都不得覆盖 GDD。
- 不把待验证、未决、暂不做或未来候选内容写成当前实现承诺。
- 未确定设计只能采用局部、可替换的 Prototype 方案，并明确标记“**v0.1临时实现，不代表最终设计**”或与目标版本一致的等效标记。

## 建立依据

1. 阅读根目录 `AGENTS.md` 和 `agents/coding.md`。
2. 读取 `docs/GDD.md` 的正文版本号、文档状态、相关范围和验收项。
3. 读取 `docs/TDD.md`，确认当前技术基线指向。
4. 读取当前版本化 TDD；涉及设计变化时再读取 `docs/DecisionLog.md` 的相关记录。
5. Godot 项目存在时，检查相关场景、脚本和验证结果；代码只能证明技术现状，不能自行改变设计。

## 选择维护模式

### 维护当前版本

当 GDD 版本没有变化，且任务只涉及当前实现细化、技术事实、风险或验证结果时：

1. 更新当前 `docs/TDD_vX.Y.md`，不创建新版本。
2. 保持 `docs/TDD.md` 的当前指向不变。
3. 将尚未实现或验证的方案保留为临时实现；只有代码和检查结果均支持时，才记录为已验证技术决策。
4. 更新文档日期和必要的技术变更记录，不把参数调试自动写成设计变化。

### 建立下一版 TDD

只有满足以下任一条件时才建立新版本：

- 用户明确要求 TDD 进入指定版本；或
- Architecture Agent 已完成 GDD 升版，并且本次任务明确包含同步技术文档。

不得仅因发现 `docs/TDD.md` 与 GDD 版本不同就自动升版。版本不一致但任务未授权同步时，报告冲突并停止切换入口。

建立新版本时：

1. 从 `docs/GDD.md` 正文读取目标版本 `X.Y`，不得从文件名或聊天记忆猜测。
2. 目标文件固定为 `docs/TDD_vX.Y.md`。
3. 若目标文件已经存在，不得覆盖；判断为维护现有目标版本，或在内容冲突时停止并报告。
4. 保留旧版 `TDD_vA.B.md`，不得覆盖、删除或改写为新版本。
5. 只继承仍符合新 GDD 的技术内容；逐项检查旧节点、模块、临时方案、风险和验收映射，不整份盲目复制。
6. 新版 TDD 完成并检查通过后，才更新 `docs/TDD.md` 的当前技术基线、对应 GDD 和日期。
7. 同步更新 `README.md` 中的当前技术文档索引；不要在 README 复制技术正文。

## 维护 TDD 内容

根据任务需要维护以下内容，不要求每次重写整份文档：

- Godot 项目与 Scene 结构；
- Script 职责和模块边界；
- 状态、事件和数据流；
- 开发顺序与 GDD 验收映射；
- 已验证技术决策、临时实现和已替代方案；
- 当前技术风险、缓解方式和剩余验证。

保持轻量。不要为当前版本未包含的 Boss、成长、关卡编辑、完整世界观、复杂技能或其他未来系统预建架构。

## 备份与一致性

- 修改现有 TDD 或入口前，按根目录 `AGENTS.md` 的统一规则将安全副本放入 `backups/docs/`。
- `docs/TDD.md` 是固定入口；`docs/TDD_vX.Y.md` 是版本化技术正文。
- 入口指向、对应 GDD 版本和 README 索引必须一致。
- 修改后检查 TDD 没有重新解释玩法、扩大范围、解决未决设计或与当前代码制造虚假一致性。

## 角色交接

- 需要改变玩法、范围、验收或 GDD 版本时，交回 Architecture Agent，并在 GDD 更新完成前停止相关 TDD 升版。
- GDD 已升版且任务包含技术同步时，由 Coding Agent 使用本 Skill 建立或更新目标 TDD。
- 调研证据不足时可交给 Learning Agent；调研结论不能直接升级为正式技术决策。

## 完成报告

报告：

- 使用的 GDD 版本与 TDD 维护模式；
- 修改、创建和备份的文件；
- `docs/TDD.md` 当前指向是否改变；
- 新增、确认、替代或仍属临时的技术方案；
- 范围检查、交叉引用和实现验证结果；
- 需要 Architecture 或 Learning Agent 跟进的问题。

除非用户明确要求，否则不要执行任何 Git 操作。
