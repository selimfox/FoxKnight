## 1. 游戏定位与核心体验

### 1.1 一句话概念 [已确认]

一个只能挥出一刀的狐狸骑士，在战前有限地调整战场条件，并在战斗中理解、利用世界规则，通过走位塑造敌人关系，最终用不可逆的一刀决定结果。

### 1.2 类型与 v0.2 工作定义 [已确认]

- 类型仍为 2D 俯视角动作解谜 Prototype。
- v0.2 暂以“反 ARPG”描述本轮设计重心：它不是取消玩家输入，而是改变力量来源——玩家的主要优势来自理解并利用世界规则，而不是持续攻击、连续输出或数值成长。该表述只服务 v0.2 验证，后续版本可以根据试玩结果重新定义，不作为项目永久类型承诺。
- 世界先按可理解的规则运行；玩家通过战前干预和战中行动改变条件；世界根据相同规则产生新局面；玩家判断如何兑现唯一一刀。

核心体验链路为：

> 有限调整初始条件 → 世界开始运行 → 观察并理解敌人差异 → 通过走位改变敌人关系 → 选择直斩或圆斩并提交唯一一刀 → 见证结果

### 1.3 设计支柱 [已确认 / 待验证]

| 支柱 | v0.2 含义 | 当前状态 |
| --- | --- | --- |
| 理解规则并创造机会 | 玩家利用地形与敌人行为形成有利局面，而不是只等待窗口自然出现 | 待验证 |
| 战前准备提供优势 | 有限调整改变初始条件，但不能替代战中走位和判断 | 待验证 |
| 不同敌人形成关系 | 步兵趋近、弓箭手保持远距，使单纯聚怪不能自动解决所有局面 | 待验证 |
| 一次攻击改变结果 | 每关仍只有一次攻击机会，直斩与圆斩共同消耗这一刀 | 已确认保留，价值待验证 |
| 行动有可预测后果 | 地形、走位、敌人响应、刀型和结果之间的因果必须可读 | 已确认目标，效果待验证 |

### 1.4 v0.2 核心假设 [待验证]

- H1：共享次数限制下的战前地形与敌人位置调整，能够让玩家主动改善初始局势，而不会直接完成整关答案。
- H2：步兵与弓箭手的不同空间行为能够共同形成值得判断的局面，而不是两种外观不同的移动目标。
- H3：玩家在战斗中的行走能够继续改变敌人位置与攻击关系，使战前布置之后仍存在有意义的决策。
- H4：直斩与圆斩能够根据战中形成的敌人分布产生实际取舍，而不是由关卡形状预先指定答案。
- H5：唯一一刀能够回报战前准备与战中塑造局面的过程，而不是继续造成克制、憋屈或“提交答案”的感受。
- H6：同一组基础规则能够支撑三个连续但不同的关卡，并让玩家产生继续、重试或尝试另一做法的动机。

## 2. v0.2 验证目标

v0.2 首先验证以下问题：

1. 玩家能否说明自己的战前调整怎样改变了开战后的局面？
2. 战前调整结束后，玩家是否仍需判断移动路线、敌人关系和出刀时机？
3. 步兵与弓箭手是否要求不同且会相互影响的处理方式？
4. 玩家是否会根据实际局面选择直斩或圆斩，并承担不同后果？
5. 一刀是否因准备过程而更有满足感，还是依然压制行动欲？
6. 三个连续关卡是否表现出规则的展开空间，而不是同一道题更换摆放参数？
7. 熟悉操作后，玩家是否仍愿意为玩法本身重试或继续下一关？

“趣味性”和“策略性”必须记录为创作者与外部玩家的主观试玩证据。自动检查不得关闭这些问题。

## 3. 玩家流程

### 3.1 单关流程 [已确认]

| 阶段 | 玩家权限 | 系统行为 | 退出条件 |
| --- | --- | --- | --- |
| 进入关卡 | 观察 | 载入本关地形、狐狸、敌人和调整次数 | 初始化完成 |
| 战前调整 | 用鼠标拖动基础地形方格或敌人；两类操作共享次数限制；可逐步撤回已提交调整；确认开始 | 根据鼠标下对象自动选择地形或敌人，不要求模式切换；降低非交互世界的亮度与饱和度；显示可操作对象、合法目标、剩余次数和撤回入口；敌人尚未运行 | 玩家确认开始 |
| 战斗运行 | 移动、观察、选择路线 | 步兵趋近狐狸；弓箭手维持远距并进行远程威胁；双方受地形可移动范围约束 | 玩家瞄准、狐狸死亡或离开关卡 |
| 瞄准与调整 | 保持移动；以鼠标选择直斩或圆斩；可以取消 | 世界继续运行，攻击范围保持可预览 | 松开左键提交或右键取消 |
| 提交唯一一刀 | 不再接受战斗输入 | 锁定刀型和攻击条件，完成攻击与命中 | 斩击完成 |
| 单关结算 | 菜单输入 | 全灭目标敌人为胜利；狐狸死亡或一刀后仍有目标存活为失败 | 重试、下一关或返回主界面 |

战前确认后，本次尝试不能再次调整地形或敌人。重试当前关时，恢复本关初始地形、角色位置、敌人状态、调整次数和唯一一刀。

### 3.2 多关卡流程 [已确认]

> 主界面 → 第 1 关 → 单关胜利 → 进入下一关 → 后续关卡 → 全部通关 → 整体胜利 → 返回主界面

- 关卡顺序与数量必须能够由项目内容配置，而不是写死在玩家流程中。
- v0.2 首轮验证内容使用 3 个连续关卡。
- 非最终关胜利后显示“进入下一关”；失败后提供“重试当前关”和“返回主界面”。
- 最终关胜利后显示全部通关结果，并提供返回主界面的入口。
- v0.2 不要求选关、进度存档、章节地图或跨关成长。

## 4. 系统规格

### 4.1 狐狸移动与生存 [已确认]

- 保留 2D 俯视角 WASD 基础移动与固定相机基线。
- 狐狸通过移动改变自身位置，并使会响应狐狸的敌人改变后续路径和空间关系。
- 狐狸没有生命值层级；受到敌人碰撞伤害或任何有效攻击伤害时立即死亡，本关失败。
- 重试后狐狸恢复到本关初始状态。

### 4.2 唯一一刀与双刀型 [已确认 / 待验证]

- 每关每次尝试只有一次攻击机会，没有普通攻击。
- 保留 v0.1 已成立的操作基线：按住鼠标左键瞄准、松开提交、瞄准时右键取消；瞄准期间不锁定移动，不启用时间缩放。
- 近身圆斩为以狐狸为中心的原地 360 度斩击；远距直斩沿鼠标方向移动并覆盖直线区域。
- 两种刀型共同消耗唯一一刀，对本轮基础敌人均保持一击必杀。
- 唯一一刀有效提交后，狐狸从提交时刻到斩击命中与胜败结果锁定期间免疫所有敌人碰撞和攻击伤害；瞄准尚未提交时仍可死亡。该规则同时适用于直斩和圆斩，避免斩击与致死碰撞在同一时刻产生结算歧义。
- 预览、刀型颜色、真实判定和执行表现继续保持一致。
- 直斩不能借由免疫穿过无基础地形区域；其预览、位移和攻击执行必须在首个不可移动边界前一致截止。
- v0.2 不证明双刀型是最终正式技能；本轮验证它们能否对动态形成的敌人分布产生真实取舍。

### 4.3 基础地形、敌人与战前调整 [已确认 / 待验证]

- v0.2 只有一类基础地形：可供狐狸和敌人移动的基础方格。
- 基础地形的分布决定狐狸与敌人的基础可移动范围；没有基础地形的位置不可移动。
- 战前调整阶段允许玩家用鼠标拖动少量基础地形方格或敌人。鼠标落在敌人身上时优先选择敌人；否则选择其下方可拖地块，因此不设置地形/敌人模式切换键。狐狸不可拖动。
- 地形与敌人调整共享同一次数池。每次合法提交消耗一次；取消、放回原位或释放到非法位置时复原且不消耗。每关次数由关卡作者设置为可调参数，并在调整阶段向玩家显示剩余次数。
- 敌人可以移到关卡内任意现有且未被狐狸或其他敌人占用的基础地形上，不限制单次距离，也不要求起点与目标之间存在可行走路径或位于同一地形区域。同一敌人可被再次移动，但每次合法移动都单独消耗一次共享调整次数。
- 战前阶段提供覆盖两类操作的统一逐步撤回。每次撤回严格恢复最近一次合法的地形或敌人调整，并返还一次调整次数；敌人撤回恢复该次拖动开始前的实际位置。没有历史时撤回入口不可用。次数耗尽后仍可撤回。开始战斗或离开关卡后不保留撤回历史。
- 战斗开始后锁定地形与敌人初始位置，不能继续调整。
- 只有未被狐狸或敌人占用的基础方格可以拖动；目标必须是关卡网格边界内的空格，且移动后所有角色仍站在基础方格上。关卡可以同时存在多个彼此独立的地形区域；地形调整可以拆分、连接或重组区域，不以全地图连通作为提交或开战条件。
- 同一关卡可以用多个 TerrainGrid 预制块辅助编辑。运行时关卡自动遍历自身场景中的全部地块、狐狸和敌人并建立统一地图，不要求关卡作者逐项登记；跨预制块相邻地块按同一四邻接地图处理。
- v0.2 仍以每关统一的正交逻辑格作为移动、寻路、拖动和直斩真值。运行时必须根据关卡内全部地块最终的世界位置自动推导逻辑格基准，因此关卡作者可以移动单个地块、整个 TerrainGrid 或其父场景，无需手工维护隐藏原点参数。地块映射只修改运行实例并记录开发警告，不改写源场景；站在地块上的角色保持相对地块的位置关系。自动映射后重复占位、超出关卡网格边界或不同逻辑格尺寸仍属于结构配置错误，并同时阻止调整与开战。多个独立地形区域是合法关卡结构，不属于配置错误。
- 角色初始位置不要求精确位于格心，只要求其占地范围落在有效基础地形内且不与其他角色重叠。未来地块可以使用非方正贴图、圆角或装饰轮廓，但 v0.2 的逻辑占地仍为规则单格；任意多边形占地、任意角度拼接与自动跨缝连通不在本轮范围。
- 关卡结构配置错误只写入开发日志，不在游戏 HUD 或结算界面显示技术诊断。独立区域数量、区域之间不可达或关卡是否存在必胜路线不作为游戏内错误提示。战前拖动到非法目标仍保留即时玩法反馈。
- 掩体是后续候选：未来可用于遮蔽感知视野或阻挡敌人前进，不属于 v0.2。

### 4.4 步兵 [已确认 / 未决]

- 步兵在战斗开始后追踪并接近狐狸，使狐狸的走位能够改变其位置和路径。
- 步兵移动速度与探测范围必须作为每个实例可调的关卡参数。
- 狐狸位于探测范围外且尚未被发现时，步兵保持原位；狐狸首次进入探测范围后，步兵在本次尝试中持续追踪，不因狐狸离开探测范围而解除。
- 步兵与狐狸位于不同地形区域或当前没有可达路径时，步兵停在自身可达地面内；以后路径重新可达时继续追踪，不得跨越虚空或瞬移。
- 步兵与狐狸发生有效碰撞时造成致死伤害。
- 步兵被任一有效斩击命中后死亡。
- v0.2 步兵只使用接触伤害，不增加独立近战攻击动作。

### 4.5 弓箭手 [已确认 / 未决]

- 弓箭手与步兵形成空间差异：倾向与狐狸保持远距，并从远处构成攻击威胁。
- 弓箭手移动受基础地形可移动范围限制，被任一有效斩击命中后死亡。
- 弓箭手的有效攻击命中狐狸时，狐狸立即死亡。
- 弓箭手在狐狸过近时远离、过远时接近，在理想距离区间内停止移动；无法找到远离路径时停止移动但仍可攻击。
- 弓箭手发射具有清楚前摇的直线箭矢；攻击开始时锁定方向，发射后不追踪狐狸。基础地形只约束移动，不阻挡箭矢；掩体仍是后续候选。
- 弓箭手与狐狸没有可达地面路径时停止趋近或远离，但仍可按既有射程与前摇规则攻击；箭矢继续允许穿过独立区域之间的虚空。
- 弓箭手的移动速度、探测范围、理想距离区间、攻击前摇、攻击间隔和箭矢速度必须作为每个实例可调的关卡参数。探测采用与步兵相同的首次发现后持续生效规则。

### 4.6 胜败、重试与关卡推进 [已确认]

- 狐狸死亡时本关立即失败。
- 唯一一刀执行结束后，所有目标敌人死亡则本关胜利；仍有目标敌人存活则本关失败。
- 失败界面提供重试当前关；重试必须恢复确定的本关初始状态。
- 失败界面同时提供返回主界面；返回后不得保留本关运行状态。
- 非最终关胜利界面提供进入下一关。
- 最终关胜利后显示整体胜利，并可返回主界面。

### 4.7 信息与反馈 [已确认]

最低需要清楚表达：

- 当前处于战前调整还是战斗阶段；除文字或图标提示外，战前调整阶段降低非交互世界的亮度与饱和度，并以独立色相和缓慢呼吸效果突出可拖方格，保持合法目标、剩余次数、撤回与开始按钮高亮；不使用无明确含义的中心点标记。
- 战前剩余调整次数、当前鼠标选择的是地形还是敌人、可选对象和目标是否合法。可拖地形悬停时增强绿色反馈；可拖敌人悬停时使用橙紫色轮廓；非法对象或目标使用红色反馈。拖动敌人时高亮关卡内全部现有空地，拖动地形时高亮空网格目标。
- 两类敌人的身份、移动意图与攻击预警；近战步兵与弓箭手必须拥有一眼可分的轮廓、装备和色彩，不能只复用同一角色图像换标签。
- 狐狸可移动区域、当前刀型、攻击范围和是否已经消耗唯一一刀。
- 狐狸死亡、单关胜败、下一关入口以及全部通关结果。

只实现会影响规则理解和试玩判断的最低反馈；不以表现扩充代替玩法验证。

## 5. 关卡与内容范围

### 5.1 v0.2 三关结构 [已确认 / 待验证]

- v0.2 提供 3 个可以按顺序游玩的默认关卡，但默认编排只用于形成第一轮可玩 Build，不代表创作者已经确认最终布局。
- 三关的具体基础地形、狐狸与敌人初始位置、敌人组合和参数、战前调整次数由创作者在 Godot 场景中直接编排和替换。
- 关卡作者可以复制多个 TerrainGrid 预制块组织地形；Level 必须自动遍历并聚合这些内容，不要求额外维护节点注册表或逐项配置引用。
- 开发阶段可以先提供一组可运行的默认三关；创作者核对后可在不修改流程代码的情况下重新摆放地面与敌人。
- 每关必须能够独立配置：基础地形布局，狐狸与敌人类型、数量和初始位置，战前调整次数，以及步兵和弓箭手的已确认行为参数。
- 三关用于比较同一组规则是否能形成不同局面。不得因为存在三份场景或能够连续通关，就认定策略性与内容延展性已经成立。

### 5.2 关卡原则 [待验证]

- 战前调整只能提供优势，不能保证胜利；开战后仍需走位、观察敌人行为、选择刀型和判断时机。
- 不同选择必须产生玩家可理解的后果；策略性不能只由隐藏数值或不可预测随机性制造。
- 地形编排应给技能用途提供线索，但不能让“走廊必用直斩、空地必用圆斩”成为固定答案。
- 至少通过三个关卡检查同一规则能否产生不同局面；完成数量本身不构成延展性成立。

## 6. v0.2 功能需求

| 编号 | 功能需求 |
| --- | --- |
| P-01 | 系统必须支持狐狸在基础地形范围内移动，并阻止其进入不可移动区域。 |
| P-02 | 每关必须支持共享可调次数上限的战前地形与敌人位置调整、严格逆序的混合撤回和次数返还；关卡允许多个独立地形区域，确认开战后锁定两类操作与清空撤回历史。 |
| P-03 | 系统必须让狐狸和敌人的可移动范围随关卡内全部基础地形的聚合分布变化，并只沿角色当前实际可达的地形区域移动。 |
| P-04 | 步兵必须按实例可调的移动速度与探测范围发现并持续追踪狐狸，接触狐狸时造成致死伤害。 |
| P-05 | 弓箭手必须按实例可调参数维持距离，并发射具有前摇、锁定方向且不追踪的直线箭矢。 |
| P-06 | 狐狸受到有效碰撞或攻击伤害时必须立即死亡并进入本关失败。 |
| P-07 | 系统必须保留每次尝试唯一一次攻击、直斩、圆斩、瞄准取消和一击必杀规则；有效提交后到结果锁定前免疫敌人伤害，直斩不得穿越不可移动区域。 |
| P-08 | 系统必须支持单关胜败、当前关重试、完整状态复原和失败时返回主界面。 |
| P-09 | 系统必须支持可配置顺序的多关卡流程；v0.2 内容使用 3 关。 |
| P-10 | 非最终关胜利后必须提供下一关入口；最终关胜利后必须显示整体胜利并提供返回主界面。 |
| P-11 | 系统必须以画面层级和明确 UI 区分战前调整与战斗，以不同颜色、轮廓和目标高亮表达可拖地块、可拖敌人与非法操作，并清楚表达两类敌人的不同外形、行为、攻击预警、调整次数、撤回状态、刀型和结算状态。 |
| P-12 | 三个默认关卡必须能够通过 Godot 场景直接配置并自动遍历多个地形预制块、角色、敌人、调整次数和行为参数；运行时依据最终场景位置自动推导统一逻辑格，兼容移动单格、TerrainGrid 或其父节点，不依赖手工原点、注册表或自研编辑器。 |

## 7. 功能验收标准

| 编号 | 关联需求 | 可观察通过条件 |
| --- | --- | --- |
| AC-01 | P-01、P-03 | 改变基础地形分布后，狐狸、步兵和弓箭手只能在自身实际可达的地形区域行动，不能进入无基础地形区域；无路可达时敌人停止移动，不跨虚空或瞬移。 |
| AC-02 | P-02 | 初始含多个独立区域时仍可调整并开战；地形调整可以拆分或连接区域。敌人可移动到任意距离、任意区域的现有空地；只有无地面、狐狸占用、其他敌人占用或原位目标非法。合法提交从共享池消耗一次，取消或非法释放复原且不消耗；混合操作严格逆序撤回并返还次数，敌人恢复该次拖动前实际位置；次数耗尽后仍可撤回；确认开始后两类调整均锁定。 |
| AC-03 | P-04、P-06 | 战斗开始后，步兵随狐狸位置变化而改变趋近路径；有效接触狐狸时狐狸立即死亡并进入失败。 |
| AC-04 | P-05、P-06 | 弓箭手依距离接近、停止或远离；前摇结束后沿锁定方向发射不追踪箭矢；有效命中狐狸时狐狸立即死亡。 |
| AC-05 | P-07 | 每次尝试只能成功提交一次直斩或圆斩；取消不消耗；有效命中的两类敌人死亡；有效提交后敌人伤害不能改变已进入执行期的结算。 |
| AC-06 | P-08 | 狐狸死亡，或一刀后仍有目标存活时显示失败；重试恢复本关地形、角色、敌人、次数和攻击机会；返回主界面后无残留战斗状态。 |
| AC-07 | P-08、P-10 | 一刀后全部目标死亡时显示本关胜利；非最终关可进入配置中的下一关。 |
| AC-08 | P-09、P-10 | 按配置顺序完成 3 关后显示整体胜利；返回主界面后不残留战斗状态。 |
| AC-09 | P-11 | 不依赖地块中心点或模式切换键时，玩家仍能从悬停反馈辨认将拖动地形还是敌人，识别相应合法目标与红色非法反馈，并能在提交前识别当前阶段、剩余次数、撤回状态、敌人类型、攻击预警、刀型及范围。 |
| AC-10 | P-12 | 不修改流程脚本、不逐项注册节点和不手调网格原点，即可复制、替换或移动多个 TerrainGrid、单个地块及其父节点；运行实例根据最终世界位置重新推导逻辑格且不改写源场景，角色保持相对脚下地块的位置关系。自动映射后的重复占位、越界或尺寸冲突会阻止调整与开战并只在开发日志给出具体原因；位置偏差和多个独立区域不会关闭拖动或开战。 |

## 8. 体验验收与试玩记录

以下内容不能由自动测试判定：

- E-01：玩家能否说明自己的地形或敌人位置调整如何改变战中局势，以及两者是否形成真正不同的选择。
- E-02：玩家在准备结束后是否仍作出路线、敌人关系、刀型或时机判断。
- E-03：玩家是否尝试过一种以上有实际后果的做法，而不是只找到明显唯一答案。
- E-04：玩家是否认为准备和走位让最终一刀更有价值，或仍然感到憋屈、被迫等待、只是提交答案。
- E-05：玩家熟悉操作后是否愿意重试或进入下一关，以及动机来自玩法、学习操作还是外部要求。
- E-06：三个关卡是否被感知为不同问题，还是同一解法的重复。

所有 v0.2 Build、功能证据和试玩观察写入 `docs/playtest/PrototypeTestLog_v0.2.md`。功能正确、视觉可读、性能表现和主观体验分别记录。

## 9. 明确暂不纳入 v0.2 [暂不做]

- 普通攻击、连击、格挡、翻滚、成长、装备和技能树。
- 多段生命值、治疗、护甲、异常状态和复杂伤害数值。
- 第三种敌人、Boss、敌人协作系统或通用行为框架。
- 掩体、视野遮挡、复杂机关、可破坏地形和战中地形编辑。
- 战前拖动狐狸、无限制自由摆放、战斗中调整地形或敌人。
- 选关、存档、章节地图、跨关成长和正式叙事流程。
- 自研关卡编辑器或敌人编辑器；继续使用 Godot 场景与必要的小型调试辅助。
- 正式美术、完整音频、商业发布和长期内容量验证。
