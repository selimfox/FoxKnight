### 2026-09-23｜v0.3 回到无拖格基线并引入锁、雕塑弹幕与续斩

- 状态：已确认机制；体验待验证。
- 所属版本：v0.3。
- 背景：创作者要求退出战前拖格，采用更明确的敌人行为，并以天之锁、反射弹、尸体冲击和异刀型续斩增加战斗中的主动行为与持续反馈。
- 决定：复用 `088c1c5` 的无拖格操作基线，新当前入口移除旧敌人并使用静止雕塑。采用首刀一次、每刀直接击杀达 N 后获一次异刀型衔接；间接击杀不计 N，但计入全灭。没有续斩时等待现有友方攻击结束再判胜败。
- 用户补充确认：瞄准弹仅发射时瞄准、之后直飞；锁使用可调冷却与刷新（默认 4 秒/2 秒）；斩击执行和选择期免疫，选择期禁止移动，末段连锁等待可移动且可受伤；正式进入 v0.3。
- 技术/编辑方向：原生 TileMapLayer 绘制静态地面和墙，独立雕塑实例与类型化弹幕列表；反射与尸体共用阵营、扫掠碰撞和寿命边界，不建立通用技能框架。
- 取舍：锁在当前固定雕塑上承担停火作用；固定位置及强制交替刀型仍可能形成唯一预排路径。慢时间窗口可能破坏节奏，需要真实试玩验证。功能通过不证明乐趣。
- 历史处理：v0.2 GDD 冻结于 `docs/archive/GDD_v0.2.md`，历史代码/技术/测试保留作对照。采用前向新增实现切换当前入口，不 reset、强推或抹去后续协作工具。用户未提交的旧 Level01 摆位保持原样且不纳入本轮提交。
- 影响：替代当前“整关只有一刀”“刀结束立即结算”“提交至结算全程免疫”和战前编辑流程；详见 GDD v0.3、TDD v0.3 和本版 Test Log。

### 2026-09-17｜关卡编排改为按最终场景位置自动映射

- 状态：已确认。
- 背景：固定 `grid_origin` 与有限对齐容差使创作者每次移动 TerrainGrid 或父场景后都可能让整关结构失效，地块和敌人随之全部不可拖动；为单次布局手调原点无法支持持续、反复的关卡编排。
- 最终决定：Level 每次载入时递归读取全部地块的最终世界位置，自动推导本关统一逻辑格基准。移动单个地块、整个 TerrainGrid 或共同父节点不要求同步维护隐藏原点。地块只在运行实例映射到推导格点，站在其上的狐狸或敌人保持相对位置；源场景不被改写。
- 错误边界：位置偏差只记录开发警告，不关闭调整或开战。自动映射后发生重复占位、超出关卡网格边界、格尺寸冲突、角色不在地面或角色重叠时仍作为结构错误阻断运行；独立区域继续合法。
- 影响范围：GDD 4.3、P-12、AC-10 与变更记录；v0.2 TDD 的聚合坐标、角色映射、结构校验、Acceptance Runner 与 Test Log。
- 追溯说明：本决定取代 2026-09-15“放宽关卡编辑位置容差并移除游戏内配置诊断”中固定原点、默认 20% 容差以及超差阻断的部分；统一正交逻辑格、运行时不改写源场景和技术诊断不进入 HUD 的部分继续有效。
- 关联提交：`a2bd851`。

### 2026-09-15｜取消敌人战前移动距离限制

- 状态：已确认。
- 背景：两格曼哈顿距离限制使视觉上明确存在的空地仍被判为不可放置，也让多个独立区域存在时的战前干预范围过小。创作者希望玩家可以自行选择并承担后果，而不是由系统以隐藏距离替玩家排除方案。
- 最终决定：敌人可在一次调整中移动到关卡内任意现有空地，不限制距离，不要求路径可达或与起点处于同一区域。目标仍不得为原位、虚空、狐狸占用格或其他敌人占用格；每次合法移动继续消耗一次共享调整次数，并进入统一撤回历史。
- 反馈规则：拖动敌人时高亮全部合法空地；超距离不再产生红色非法反馈。活动拖动期间暂时禁用开始战斗，释放或取消后恢复，这只用于避免在对象悬空时开始，不限制最终选择。
- 设计风险：玩家可能直接把敌人排成一刀答案；不添加新的隐藏反排阵限制，继续通过关卡编排和试玩验证 OQ-03。
- 影响范围：GDD 4.3、4.7、AC-02 与变更记录；v0.2 TDD、敌人拖动目标高亮和 Acceptance Runner。
- 追溯说明：本决定取代同日“共享战前调整”中敌人单次曼哈顿距离不超过 2 格的限制；共享次数、目标占用和撤回规则继续有效。
- 关联提交：`a2bd851`。

### 2026-09-15｜允许多个独立地形区域正常开战

- 状态：已确认。
- 背景：Level01 由三条各自连续但彼此分开的横向地面组成。此前实现把“所有地块必须组成一个全局连通分量”当作开战条件，导致视觉和关卡意图都合法的多个区域被错误阻止。
- 最终决定：取消初始化、地形提交和开战阶段的全地图单一连通要求。一个关卡可以包含多个独立地形区域；地形调整可以拆分或连接区域。结构有效且没有正在拖动的对象时即可开始战斗。
- 行为边界：狐狸、步兵和弓箭手只在自身实际可达的地面内移动；无路径时敌人停止移动，不跨虚空或瞬移。弓箭手箭矢保持可穿越虚空，直斩仍在首个无地面处截止，圆斩保持既有范围判定。敌人战前重新放置仍按两格曼哈顿距离和目标空地规则，不要求中间路径。
- 不做的检查：不自动判断全局必胜、所有步兵必须能接近狐狸或所有区域必须有角色；这些属于关卡编排与试玩结果，不作为配置错误或开战门槛。
- 影响范围：GDD 3.1、4.3～4.5、4.7、P-02/P-03、AC-01/AC-02/AC-10 与变更记录；v0.2 TDD 的聚合状态、开战条件、路径行为和验收。
- 追溯说明：本决定取代同日“允许战前调整修复不连通地形”中最终必须连通才能开战的结论；其结构错误与战前可调整部分继续有效。
- 关联提交：`a2bd851`。

### 2026-09-15｜允许战前调整修复不连通地形

- 状态：已确认。
- 背景：实现把初始不连通与结构损坏共同归为无效配置，并据此禁用全部拖动，导致玩家无法使用战前调整把地形连接起来，与该阶段主动改变初始局面的用途冲突。
- 最终决定：将“结构有效”和“可以开战”分离。重复占位、尺寸冲突、超出吸附容差、无地面、角色不在地面或初始重叠继续同时阻断调整与开战；地形不连通只阻断开战。结构有效时允许拖动地形、拖动敌人和撤回，地形调整的中间状态可以保持或增加连通分量，最终全部地形四方向连通后才启用开始战斗。
- 反馈规则：未连通属于玩家可修复的玩法状态，普通提示区显示“地形尚未连通，请调整或撤回”，不显示节点路径、坐标或分量数；结构错误详情只写开发日志。次数耗尽但仍未连通时，玩家仍可通过撤回返还次数。
- 当前关卡验证：Level01 当前四个连通分量可以在两次地形调整内连接：先将下行左端逻辑格 `(2,5)` 移到主行缺口 `(6,3)`，再将上行左端 `(2,1)` 移到 `(6,4)`。这只证明准备阶段存在可行连接，不证明战斗通关或体验成立。
- 否决方案：不要求每次中间调整都保持连通或减少分量；不加入全局解题器，不自动补格、增加次数或修改作者场景。
- 影响范围：GDD 3.1、4.3、4.7、P-02、AC-02、AC-10 与变更记录；v0.2 TDD 的状态拆分、拖动合法性、HUD 与验收。
- 关联提交：`a2bd851`。

### 2026-09-15｜放宽关卡编辑位置容差并移除游戏内配置诊断

- 状态：已确认技术与呈现规则；非方正逻辑占地仍属后续范围。
- 背景：创作者的第一关地块存在数像素到约十像素的手工摆放偏差，现有 0.5 像素硬对齐会把视觉上可接受的编辑误差全部判为配置错误；游戏 HUD 同时暴露了节点对齐、连通等开发诊断。
- 最终决定：每关继续使用统一正交逻辑格，但位置容差改为关卡可调比例，默认每轴为格尺寸的 20%。容差内 TerrainCell 在运行实例吸附到最近逻辑格，不改写源场景；超过容差、吸附后重复、尺寸冲突或真实断路继续阻止开战。角色不要求位于格心，只验证占地位于有效地面且初始不重叠。配置错误只汇总到开发日志，不显示在 HUD；拖动非法目标的玩法反馈保持不变。
- 设计边界：地块视觉可以使用非方正贴图、圆角和装饰轮廓，当前逻辑占地仍为一个规则方格；本决定不引入任意多边形占地、任意角度拼接、自动跨缝连通、八方向连通或孤岛地图。
- 影响范围：GDD 4.3、P-12、AC-02、AC-10、变更记录，v0.2 TDD 聚合校验、角色占地、撤回与 HUD 错误呈现，Acceptance Runner 与 Test Log。
- 当前关卡事实：Level01 的轻微坐标偏差可由新容差处理，但凸起地块与主行仅形成斜角关系、下方整行缺少连接，按现有四方向规则仍为四个连通分量；本决定不替创作者重排或补桥。
- 关联提交：`a2bd851`。

### 2026-09-15｜共享战前调整并由关卡自动聚合地形预制块

- 状态：已确认机制；体验效果待试玩验证。
- 背景：禁止移动角色脚下地块与破坏连通度后，简单关卡中可移动地块过少；创作者同时使用多个 TerrainGrid 预制块组织关卡，希望复制预制块只承担编辑便利，而不产生彼此独立的运行地图。
- 最终决定：战前允许拖动未占用基础地形或敌人，两类操作共享每关调整次数与严格逆序撤回。鼠标下存在敌人时优先拖敌人，不增加模式切换键；狐狸不可拖动。敌人只能移到两格曼哈顿距离内的现有空地，不要求中间路径。Level 自动遍历关卡场景中的全部 TerrainGrid、地块、狐狸和敌人，建立统一运行地图；无需逐项注册。重复坐标、格尺寸不一致、格点未对齐或初始地图不连通时阻止开战并报告配置错误。
- 否决方案：不继续依靠单一 TerrainGrid 节点路径；不要求创作者把所有地块手工归入一个节点；不加入 R 键切换拖动模式；不为防止战前排阵加入隐藏限制。
- 影响范围：GDD H1、战前流程、基础地形规格、反馈、P-02/P-03/P-11/P-12、AC-02/AC-09/AC-10、E-01、OQ-03、v0.2 TDD、地形运行真值与撤回结构。
- 后续验证：重点观察直接移动敌人是否压倒移动地形、是否能在战前排出明显一刀答案，以及开战后是否仍需路线、刀型和时机判断。
- 追溯说明：本决定取代 2026-09-12 记录中“敌人初始位置运行时编辑不纳入 v0.2”的范围结论；旧记录保留，不回写历史。
- 关联提交：`a2bd851`。

### 2026-09-13｜修订 v0.2 战前地块识别与撤回

- 状态：已确认
- 所属版本：v0.2
- 原问题或原方案：所有地块使用近似颜色并以中心圆点表示可交互性，圆点含义不清；合法移动一旦提交便无法撤回；步兵与弓箭手复用同一角色图像，只靠颜色和文字区分。
- 最终决定：删除地块中心点，以区别于普通地面的颜色和缓慢呼吸效果标示可拖地块；加入逐步撤回，恢复最近一次合法调整并返还次数；为步兵和弓箭手使用轮廓、装备与色彩明确不同的角色形象。
- 决定原因：让战前可操作对象无需阅读说明即可被识别，降低有限次数下的误操作成本，并让敌人身份在动态战斗中能由形象直接辨认。
- 影响范围：战前调整流程、地块反馈、HUD、敌人视觉、P-02、P-11、AC-02、AC-09 与 v0.2 TDD。
- 关联GDD章节：第 3.1、4.3、4.7、6、7、11 节。
- 后续验证：检查首次玩家是否能在没有中心点的情况下找到可拖地块、理解撤回返还次数，并在不读头顶标签时区分步兵与弓箭手。
- 补充说明：不改变战前调整次数上限、合法性规则或两类敌人的行为规则。

### 2026-09-12｜建立 v0.2 主动塑造局面验证范围

- 状态：已确认范围；具体数值与最终三关编排待试玩和创作者调整
- 所属版本：v0.2 Prototype
- 原问题或原方案：v0.1 已证明移动、瞄准和双刀型可运行并具有不同空间用途，但体验主要退化为“识别位置—等待窗口—提交答案”。原先只依次孤立测试一个响应行为和一个轻量关卡组件的方案，不能完整呈现创作者希望验证的战前准备、战中塑造局面与唯一一刀兑现链路。
- 最终决定：v0.2 以“让简单 Demo 呈现基础趣味性和策略性”为上位目标。保留唯一一刀、原地圆斩与远距直斩；加入鼠标拖动且受次数限制的战前基础地形调整、可调速度与探测范围的追踪步兵、维持距离并发射预警直线箭的弓箭手、狐狸受到碰撞或攻击后一击死亡、提交一刀后的结算期伤害免疫，以及三个可配置连续关卡和完整关间流程。“反 ARPG”只作为 v0.2 工作定义。敌人初始位置运行时编辑、掩体和自研内容编辑器不纳入 v0.2。
- 决定原因：创作者确认目标是理解世界规则并主动利用规则创造出刀机会；仅靠固定巡逻与等待窗口不足以表达该目标。两种空间行为不同的敌人用于形成关系，有限战前干预用于改善初始条件，战中走位和双刀型继续承担机会塑造与兑现。
- 变量边界：敌人行为与战前地形调整同属 v0.2，但仍应分阶段实现、分别留存证据，再进行组合验证；不得用最终组合 Build 反向宣称单项假设已经成立。
- 影响范围：GDD v0.2 全文、后续 `PrototypeTestLog_v0.2.md`、待建立的 TDD v0.2，以及 Prototype 的敌人、地形、伤害、关卡流程与 UI 范围。
- 关联GDD章节：第 1～12 章。
- 后续验证：Coding Agent 先建立可由 Godot 场景直接配置的关卡骨架和一组默认三关；创作者随后调整最终地形、敌人和参数。功能通过只证明规格运行；趣味性、策略性、一刀价值和三关延展性必须通过创作者及外部玩家试玩记录判断。
- 后续修订：其中“敌人初始位置运行时编辑不纳入 v0.2”已由 2026-09-15 的共享战前调整决定取代；其余范围结论继续有效。

### 2026-08-26｜正式结束 v0.1 并将下一阶段聚焦主动塑造局面

### 2026-08-17｜用切换圈与双色反馈预告双刀型边界

- 状态：实验中
- 所属版本：v0.1；不升级 GDD 或 TDD 版本
- 原问题或原方案：朋友测试者在事先阅读“近弧／远直”说明后能够区分两种已显示的刀型，但创作者指出当前没有实时标示距离阈值，玩家只能在预览形状已经切换后得知结果；狐狸瞄准期移动还会在鼠标不动时改变相对距离，唯一一刀因此存在提交前意外换型的公平性风险。现有两种预览也基本共用金橙色，形状可辨但视觉语义没有分层。
- 最终决定：v0.1 瞄准期间显示以狐狸为圆心、半径等于当前刀型距离阈值的弱化切换圈；每次鼠标或狐狸实际跨圈导致 `ARC/STRAIGHT` 切换时，切换圈播放一次短促 UI 光效和一次轻微占位音效，同一刀型内不重复触发。近身弧形斩使用暖橙／金色，远距直线斩使用冷青／蓝白色，颜色至少贯穿瞄准范围、方向线与执行刀光。
