### 2026-08-19｜弧形斩改为原地斩并让有效半径直接承担刀型边界

- 状态：实验中
- 所属版本：v0.1；不升级 GDD 或 TDD 版本
- 原问题或原方案：移动弧斩同时承担近身范围攻击与短距离位移，和本就带位移的直线斩定位冲突；瞄准圆只能表达提交瞬间范围，无法一次准确表达“圆形判定随位移扫过”的真实命中集合。独立刀型阈值又在弧斩攻击圆外形成第二个圆，增加被理解为第二层攻击范围的风险。
- 最终决定：近身弧形斩取消短位移、鼠标方向死区和位移箭头，固定为以提交位置为圆心的原地 360 度斩击。刀型切换距离不再作为独立可调参数，直接使用应用命中宽容度后的弧斩有效半径：鼠标距离 `<` 有效半径选择 `ARC`，`>=` 选择 `STRAIGHT`。弧斩状态只显示一个暖橙攻击圆，其边缘同时是切换边界；直斩状态保留同半径、低亮度、无填充且仅改变透明度的暖橙弧斩区提示圈。既有跨界闪光、轻微占位音效、双色刀型语言和直线斩逻辑保持。
- 决定原因：让两种刀型形成清楚分工——弧斩负责近身原地覆盖，直斩负责远距方向与位移；同时让“选择边界、预览、判定、刀光”共用一个有效半径，消除移动弧斩无法完整预告命中路径和双圆信息重复的问题。
- 影响范围：P-02、P-03、P-05、P-08、P-09，AC-01～AC-03、AC-06、AC-09，OQ-04、OQ-11，GDD、TDD、Prototype 与自动验收；不改变唯一一刀、取消规则、一击必杀、胜败结算、直线斩或敌人编排。
- 关联GDD章节：第 3.1、4.2、6、7、11、12 章及 `PrototypeTestLog_v0.1.md` A.10。
- 后续验证：确认弧斩状态只有一个攻击圆且执行全程原地；直斩状态弱圈能够提示回到弧斩区但不会被误读为第二层攻击；跨界在 `< / >=` 边界准确切换；命中宽容度只应用一次；创作者实玩比较原地弧斩与移动弧斩的定位清晰度、操作感和仪式感。
- 当前实现与初测：2026-08-19 已移除 Level 的 `slash_form_distance_threshold`、`arc_move_distance`、`arc_direction_deadzone_radius` 导出参数和 Player 的 `DeadzoneOutline`；弧斩执行固定在提交位置。Godot 4.7.1 Headless Smoke Acceptance 全部通过，覆盖参数共源、边界两侧、单圈显示、直斩弱圈呼吸、双向跨界反馈、原地执行、圆内命中、圆外存活及直线斩／取消／结算回归。D3D12 捕获确认弧斩单圈、直斩弱暖橙圈、双向跨界闪光及原地同心刀光；执行帧 Player 与 Slash 位移差均为 0，刀光半径为 100。
- 补充说明：自动通过只证明功能边界正确，不证明 H5、整体可玩性或“原地弧斩更好玩”已经成立；本轮不改敌人布局、不增加第三刀型、迟滞区、教程或新的结果演出。

### 2026-08-17｜将常驻阈值圈改为反色的下一刀型预告圈

- 状态：被替代（2026-08-19 起只在直斩状态保留暖橙弧斩区提示圈）
- 所属版本：v0.1；不升级 GDD 或 TDD 版本
- 原问题或原方案：首版切换圈使用中性弱紫色常驻，仅说明边界位置。创作者希望进一步降低玩家把外圈误读为第二层攻击范围的风险，并让它在不依赖文字时直接说明“跨过边界会切成什么刀型”。
- 最终决定：切换圈正式定义为“下一刀型预告圈”。当前为近身弧形斩时，外圈使用代表远距直线斩的轻微蓝白色；当前为远距直线斩时，外圈使用代表近身弧形斩的轻微橙色。常驻状态采用低强度呼吸灯，但只改变透明度，不改变半径、线宽或填充；实际跨圈仍使用明显更强的目标刀型颜色扩散闪光与轻微切换音效。
- 决定原因：当前攻击预览继续回答“现在松开会出什么刀”，反色外圈回答“跨过这里会变成什么刀”；把当前结果与下一状态分层表达，同时以低亮度、无填充和固定半径避免预告圈获得攻击范围的视觉重量。
- 影响范围：刀型阈值圈常驻颜色与动画语义、P-08、AC-01、OQ-11、TDD 与 Prototype；不影响攻击判定、阈值数值、切换音效或两种刀型的当前状态颜色。
- 关联GDD章节：第 4.2、6、7、11、12 章及 `PrototypeTestLog_v0.1.md` A.9。
- 后续验证：确认近弧状态为蓝白预告圈、远直状态为橙色预告圈；呼吸过程中半径和线宽不变；跨圈闪光明显强于常驻呼吸；首次玩家能够区分“当前攻击范围”和“下一刀型预告圈”，并回答外圈本身不会造成伤害。
- 当前实现与初测：2026-08-18 已将 `FormThresholdOutline` 改为反色下一刀型预告：`ARC` 显示蓝白、`STRAIGHT` 显示橙色；常驻透明度在 0.18～0.34 之间按 1.6 秒周期呼吸，节点缩放、点集半径和线宽不参与动画。更新后的完整 Smoke Acceptance 通过，覆盖反色映射、透明度变化、固定半径／缩放／线宽及既有切换、输入、命中和结算回归；D3D12 六状态捕获确认常驻圈弱于当前攻击范围，跨圈闪光明显更强。未知规则玩家是否仍将外圈误读为攻击范围尚未验证。
- 补充说明：本轮不加入区域填充、文字标签、迟滞区或新的音效；呼吸参数只是 Prototype 起点，主观强弱仍需创作者与未知规则玩家实玩确认。

### 2026-08-17｜用切换圈与双色反馈预告双刀型边界

- 状态：实验中
- 所属版本：v0.1；不升级 GDD 或 TDD 版本
- 原问题或原方案：朋友测试者在事先阅读“近弧／远直”说明后能够区分两种已显示的刀型，但创作者指出当前没有实时标示距离阈值，玩家只能在预览形状已经切换后得知结果；狐狸瞄准期移动还会在鼠标不动时改变相对距离，唯一一刀因此存在提交前意外换型的公平性风险。现有两种预览也基本共用金橙色，形状可辨但视觉语义没有分层。
- 最终决定：v0.1 瞄准期间显示以狐狸为圆心、半径等于当前刀型距离阈值的弱化切换圈；每次鼠标或狐狸实际跨圈导致 `ARC/STRAIGHT` 切换时，切换圈播放一次短促 UI 光效和一次轻微占位音效，同一刀型内不重复触发。近身弧形斩使用暖橙／金色，远距直线斩使用冷青／蓝白色，颜色至少贯穿瞄准范围、方向线与执行刀光。
- 决定原因：切换圈负责预告“何时换刀”，双色视觉语言负责确认“现在是哪一刀”，短促视听反馈负责确认“刚刚发生了切换”；三者分别解决不同信息层，不依赖玩家记住教程或在释放瞬间猜测阈值。
- 影响范围：双刀型瞄准预览、执行刀光、轻量 UI 反馈、临时音频资源、P-08、P-09、AC-01、AC-06、OQ-11、TDD 与 Prototype。
- 关联GDD章节：第 4.2、4.6、6、7、11、12 章及 `PrototypeTestLog_v0.1.md` A.7～A.8。
- 后续验证：确认切换圈半径与真实阈值一致且不被误读为攻击范围；在鼠标移动与狐狸移动两种跨圈方式下，每次实际切换只触发一次光效和音效；近弧／远直的预览与执行颜色一致；记录阈值附近是否出现频繁闪烁或音效连发，再决定是否需要迟滞区。
- 当前实现与初测：2026-08-17 已实现与 `slash_form_distance_threshold` 共参的弱紫切换圈、0.18 秒对应刀型颜色圈层光效、暖橙近弧／冷青远直的预览与执行映射，以及 Kenney UI Audio CC0 `switch14.ogg` 轻微占位声（引擎报告约 0.033 秒，场景音量 -16 dB）。更新后的 Smoke Acceptance 全部通过，覆盖初次进入不触发、同侧不重复、双向跨圈各触发一次、阈值圈共参、音频资源存在和既有状态／命中回归；D3D12 捕获确认稳态和切换态可区分。主观听感与首次玩家是否误读外圈仍待人工验证。
- 补充说明：本轮不制作完整新手导览，不加入第三刀型、轨迹输入或新的攻击机会；轻微切换音效为许可清楚、可替换的 Prototype 占位资源，不代表最终音色。

### 2026-08-17｜弧形斩短位移改由鼠标方向与可调死区决定

- 状态：被替代（2026-08-19 起弧形斩固定原地执行，不再需要方向死区或位移箭头）
- 所属版本：v0.1；不升级 GDD 或 TDD 版本
- 原问题或原方案：弧形斩短位移原本在松开左键时采样 WASD。玩家若想向指定方向位移，必须在出刀前已经保持该方向移动；WASD 同时承担站位移动和攻击位移选择，形成不易预告的时序与组合输入负担。
- 最终决定：弧形斩短位移方向改为狐狸指向鼠标。鼠标距离继续选择刀型，鼠标角度选择方向；新增可调的圆形方向死区，默认半径 24。弧形瞄准始终显示死区圆；鼠标位于死区外时显示从圆心指向鼠标、长度等于边界裁剪后实际短位移的箭头，位于死区内时隐藏箭头并提交原地弧形斩。WASD 只用于瞄准期移动狐狸。
- 决定原因：让玩家在松开前直接确认弧形斩是否位移、朝哪里位移以及实际位移多远，消除必须预先保持 WASD 的隐藏操作条件；同时保留鼠标与狐狸重合时稳定、明确的原地斩分支。
- 影响范围：弧形斩输入映射、瞄准预览、可调参数、P-03、P-08、AC-01、AC-02、OQ-11、TDD 与 Prototype。
