## 1. 记录原则

- 本文件只记录 v0.2 Build 的功能验收、视觉证据、性能证据和人工试玩观察，不定义玩法。
- 每次记录必须注明 Build 或提交、日期、场景、关键参数、初始条件、操作步骤、预期、实际结果、关联 GDD 需求与结论。
- 功能正确、画面可读、性能表现和主观体验分别记录；自动验收不得证明趣味性、策略性、一刀价值或重试动力成立。
- v0.1 证据继续保存在 `PrototypeTestLog_v0.1.md`，不得混写。

## 2. v0.2 重点观察

- 玩家能否说明战前调整怎样改变开战后的局面。
- 战前准备后是否仍需作出移动路线、敌人关系、刀型或时机判断。
- 步兵与弓箭手是否形成不同且相互影响的空间问题。
- 唯一一刀是否回报准备过程，或仍然造成等待、克制和答案提交感。
- 三个连续关卡是否形成不同问题，以及玩家是否愿意重试或继续。

#### 功能证据

- 三关按配置顺序载入；单关胜利可进入下一关；第三关完成后进入整体胜利；失败可重试本关或返回主界面。
- 合法拖动只消耗一次调整，非法拖动不消耗；调整后地面保持四向连通，角色仍站在地面上。
- 玩家与步兵均可跨越相邻地面格；直斩可跨越连续地面，并在虚空前停止。
- 步兵速度与探测范围、弓手速度、探测范围、距离区间、蓄力时间、射击间隔和箭速均可在场景实例中配置。
- 步兵首次发现狐狸后持续追击；弓手按距离接近、撤退或瞄准，蓄力开始后锁定方向，箭直线飞行。
- 狐狸在战中受到敌人接触或箭矢伤害时一击失败；有效出刀提交后至结算期间无敌。

#### 视觉证据

- 战前画面压暗角色与背景，地面格、可交互提示、剩余次数和开始按钮保持高亮。
- 战中恢复正常亮度；步兵与弓手使用不同色调，并以中文标签显示追击、接近、撤退、瞄准或射击意图。
- 旧 v0.1 场景中没有规则作用的装饰路径、符文、房间标题和贴花已移除；碰撞边界及回归所需地面保留。
- 截图：`output/v02_prepare.png`、`output/v02_battle.png`、`output/v02_result.png`。

#### 当前结论

- **功能结论：通过。** v0.2 已具备让用户自行摆放三关并调整敌人参数的可试玩骨架。
- **体验结论：未验证。** Agent 控制试玩只能证明完整链路可运行，不能证明默认三关有趣、有策略性，也不能证明战前调整不会把战斗降为答案验收。
- 下一步必须由用户实际摆放或修改关卡并试玩，重点记录地形调整是否改变战中路线与刀型判断，以及两类敌人是否形成相互影响的空间问题。

### B.2 战前交互修订与 GPT-6 Astra 代理试玩

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-13 |
| Build | `a2bd851`（首次纳入仓库；测试时为提交前工作区）；Godot 4.7.1 stable |
| 变更 | 删除地块中心点；可拖地块使用绿色缓慢呼吸；加入逐步撤回；步兵与弓手使用不同角色图像；修正弓手无退路时仍可射击 |
| 自动功能验收 | `RESULT \| PASS \| v0.2 functional acceptance` |
| v0.1 回归 | `RESULT \| PASS \| Prototype smoke acceptance` |
| D3D12 控制试玩 | `RESULT \| PASS \| v0.2 agent playtest` |
| Astra 试玩 | GPT-6 Astra 以运行时输入分别尝试三个默认关卡；未改敌人位置、参数、生命、AI 或胜败状态 |

#### 功能与视觉证据

- 只有当前确实可合法移动、未被角色占用且仍有调整次数的地块显示准备色与呼吸；不再绘制中心点。
- 连续两次合法移动、两次倒序撤回、次数返还、空历史拒绝、开战清空历史均通过自动验收；三个关卡均实际执行过拖动与撤回。
- 撤回与开始战斗按钮已移到默认网格右侧纵向排列，与地块和底部提示没有重叠。
- 步兵使用重甲、盾与短剑轮廓；弓手使用兜帽、弓与箭袋轮廓。两者在默认显示尺寸下可以直接区分。
- 弓手过近且没有更远可达格时停在原地并开始蓄力射击，避免“逼到墙边即可停火”。

#### Astra 实际行为与结果

- 第 1 关：不调整地形、不移动，原地等待约 2.1 秒后向右直斩，三个敌人全部死亡并进入下一关；提前约 0.2 秒出刀只杀死弓手。顺时针或逆时针绕场可存活约 10 秒，但一次直斩只杀 2 个、留下 1 个。
- 第 2 关：站定、向左下移动、先左上再右移三种尝试均失败。两侧弓手使路线产生不同后果，但四名敌人同时激活，学习窗口较短；三次失败不足以证明关卡无解。
- 第 3 关：站定、向左下和向左上三种尝试均失败。主要感受是多方向夹击，尚未显示区别于第 2 关的新规则理解；增加数量与压力本身不能证明规则展开。
- 证据：`work/astra_playtest.log`、`output/astra_L1_T0_stationary_timed_straight_aim.png`、`output/astra_L1_T0_stationary_timed_straight_result.png`。

#### 体验结论

- **明确负面证据：** 默认第 1 关存在“等待自然成局 → 提交直斩”的可靠退化解；H1 与 H3 未被该关验证。
- **初步正面迹象：** 出刀早晚约 0.2 秒会改变命中结果，敌人路线也会随狐狸移动发生变化；说明时机和路线具备可学习后果。
- **仍未成立：** 当前满铺矩形地面没有清楚说明移动某块地会怎样改变追击路径；战前调整在默认三关中的必要性与策略价值尚无证据。圆斩与直斩也尚未形成稳定取舍证据。
- 下一次人工调关应先改变地形与初始位置，随后一次只调一组行为参数；不能用普遍增速、加敌人或扩大刀范围掩盖关系问题。

### B.3 多地形块聚合与共享敌人调整

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-15 |
| Build | `a2bd851`（首次纳入仓库；测试时为提交前工作区）；Godot 4.7.1 stable |
| 场景 | 运行时构造的合法双 TerrainGrid Level02、错误配置夹具、当前用户编排 Level01、默认 Level03 |
| 关键配置 | 地形与敌人共享 3 次调整；敌人可放到任意距离、任意独立区域的现有空地；双 chunk 共同形成 35 格聚合地图 |
| 自动功能验收 | `RESULT \| PASS \| v0.2 functional acceptance` |
| v0.1 回归 | `RESULT \| PASS \| Prototype smoke acceptance` |
| D3D12 确定性窗口测试 | `RESULT \| PASS \| v0.2 agent playtest`；由本地 Godot 脚本执行固定输入，不调用 Astra；确认 Level01 多区域直接可调整和开战，并覆盖远距离敌人拖动、区域变化、撤回、跨格移动和圆斩结算 |
| 渲染环境 | Windows D3D12 Forward+；NVIDIA GeForce RTX 4060 Laptop GPU |

#### 功能证据

- Level 能递归发现任意层级下的 TerrainGrid、TerrainCell、狐狸和两类敌人，并建立唯一运行地图；测试把一格地形、狐狸和一名步兵移出约定容器，仍能自动聚合，无需注册数组或节点路径。
- 跨 TerrainGrid 边界的相邻地块由同一占用字典处理；玩家可行走查询、敌人寻路与直斩虚空截止均读取该聚合地图。
- 鼠标可拖动敌人或地形，敌人脚下地块不可拖，因此同一位置优先选择敌人；狐狸没有战前拖动入口。
- 敌人可以移动到任意距离及任意独立区域的现有空地，不要求起点与目标之间存在路径；同格、虚空、狐狸占地和其他敌人占地仍拒绝。
- 当前 Level01 中，位于上方区域的步兵可以拖到截图所示的中间区域同列空地；该真实场景目标已加入自动验收并通过。
- 敌人移动与地形移动共用次数和同一历史栈；交错提交后逐次撤回严格按相反顺序恢复对象并返还次数。开始战斗后清空历史并禁用两类拖动。
- Level 默认允许 TerrainCell 每轴偏差不超过格尺寸的 20%；容差内节点只在运行实例吸附，源 `.tscn` 内容保持不变，并由一次汇总 warning 记录。超差、吸附后重复、不同 `cell_size`、角色占地越界或重叠属于结构错误，会同时禁用调整与开始。
- 角色无需位于格心；合法夹具中的狐狸和敌人分别偏离格心后，只要完整占地圆仍在地面且彼此不重叠，配置即可通过。角色占地越界与初始重叠分别有具体错误。
- 敌人从非格心位置拖到目标格心后，混合撤回会恢复拖动开始前的精确世界坐标，而不是恢复为起点格心。
- 多个独立地形区域不影响结构或开战状态；Level01 初始即可拖动地形、拖动敌人并直接开战。地形调整可拆分或连接区域，提交和撤回期间 Start 只随结构有效性与当前是否正在拖动变化。
- 独立双区域夹具确认步兵和弓箭手找不到四邻接路径时保持原位，不会退化成朝目标直线穿越虚空；弓箭手仍按距离规则进入射击前摇。
- 同一夹具确认箭的既有远程攻击入口保留，直斩距离在首个空隙前截止，不能抵达远端独立区域。

#### 视觉证据

- 敌人拖动时，全图所有合法空地以明亮绿色显示，拖动对象使用合法或非法轮廓；HUD 明确显示“敌人：可放置”或“敌人：不可放置”。
- 地形拖动继续用绿色或红色显示释放是否合法；普通可拖地面保持准备色与缓慢呼吸。
- 结构错误只写开发日志；独立区域数量不产生 HUD 提示、warning 或 error。
- `output/v02_independent_regions.png` 显示 Level01 三片独立地形同时存在，地形仍高亮可拖且 Start 初始启用；提示区没有连通性诊断。
- 其余截图：`output/v02_enemy_drag.png`、`output/v02_terrain_drag.png`、`output/v02_prepare.png`、`output/v02_battle.png`、`output/v02_result.png`。

#### 当前阻塞与结论

- **系统功能结论：通过。** Level01 的多个独立区域可直接调整和开战；敌人可跨任意距离及独立区域重新放置；区域拆分/连接、无路径敌人停留、弓手继续射击、直斩空隙截止、合法多 chunk 聚合及既有战斗链路均通过自动与窗口验收。
- **关卡事实：** `level_01.tscn` 的源布局保持不变；其独立区域现在属于合法关卡结构。系统不判断各区域是否都有角色、敌人能否接近狐狸或是否存在必胜路线。
- **性能证据：未专项采样。** D3D12 确定性窗口测试期间未出现影响流程的卡顿，但这不能替代帧时间或长时间运行测试。
- **体验结论：未验证。** 自动与确定性窗口测试不能判断敌人调整是否压倒地形调整，也不能证明战前布置之后仍有值得判断的路线、刀型与时机。修正 Level01 后仍需创作者及未知规则玩家试玩 H1～H6。

### B.4 关卡编排自动网格映射

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-17 |
| Build | `a2bd851`（首次纳入仓库；测试时为提交前工作区）；Godot 4.7.1 stable |
| 触发场景 | 创作者再次移动 Level01 的 TerrainGrid 与敌人后，固定 `grid_origin` 将地块判为超出容差并关闭全部拖动 |
| 自动功能验收 | `RESULT \| PASS \| v0.2 functional acceptance` |
| v0.1 回归 | `RESULT \| PASS \| Prototype smoke acceptance` |
| D3D12 确定性窗口测试 | `RESULT \| PASS \| v0.2 agent playtest`；本轮未调用 Astra |

#### 功能证据

- Level01 不再保存为当前布局特调的 `aggregate_grid_origin`。聚合器按全部 TerrainCell 的最终世界位置自动推导本轮网格相位与原点；当前 TerrainGrid2、TerrainGrid3 和敌人新位置可直接进入调整并开战。
- 专项夹具同时移动 Level 根节点、分别移动两个 TerrainGrid、单独偏移一个 TerrainCell，并让狐狸与敌人跟随各自区域编辑位置。聚合后结构有效、Start 启用、地形与敌人均可拖动，敌人提交与撤回通过。
- 地块位置偏差改为开发 warning，不再单独使结构无效；运行时映射仍不改写 `.tscn`。角色应用脚下作者地块的同一映射位移，保持相对地块位置。
- 自动映射后的重复坐标、超出 `grid_bounds`、不同 `cell_size`、角色不在地面或角色重叠仍属于结构错误，并继续阻断调整与开战。
- 当前第一关实际窗口完成地形拖动、敌人拖动、提交和撤回；截图为 `output/v02_level01_terrain_drag.png` 与 `output/v02_level01_enemy_drag.png`。

#### 结论

- **功能结论：通过。** 关卡作者可以通过移动单格、TerrainGrid 或其父节点反复调整布局，无需随场景维护固定原点；当前第一关地块和敌人均恢复可拖。
- **边界：** v0.2 仍映射到统一正交逻辑格。任意旋转、非统一缩放、重叠地块和任意多边形占地不在本轮范围。
- **体验结论：未验证。** 本轮只证明编辑编排与运行映射可靠，不证明第一关策略性或趣味性成立。
