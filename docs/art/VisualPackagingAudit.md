# 《狐狸骑士》现有构建视觉包装审计与 Art 交接

> 2026-09-26；Architecture 视角。本文不是 GDD、TDD、正式美术设定或版本升版文件。它把玩家必须读懂的信息、当前缺口和验收问题交给 Art；视觉方案与资源制作由 Art 提案，接入方式由 Coding 决定，审美方向由创作者确认。

> **本轮用户确认（覆盖下文较早的「未决」措辞）**：第一关左上区域按纯视觉浅水制作，狐狸与敌人照常走过，碰撞和斩击判定不变，进入水域才显示随动作变化的倒影。本轮完整包装当前可运行的三关、一名狐狸、一类追踪士兵、双刀型及现有菜单／HUD／结算；不新增玩法或叙事。这是美术制作范围确认，尚不等于 GDD 版本或玩法基线升版。

## 0. 来源冲突与范围

`docs/GDD.md` 与 `docs/TDD.md` 仍把 **v0.1 阶段结算**作为正式且冻结的当前基线：单房间、移动和站位、鼠标距离双刀型实验、一次攻击、自动胜败、快速重试。GDD 第 8、11、14 章明确关卡元结构、敌人伤害、成长、剧情身份等尚未进入该版本。工作树的 `project.godot` 却已启动 `campaign.tscn`，含主菜单、三关、追踪士兵及第一关庭院底图；这些是**当前构建事实，不等于已被 GDD 确认的新版设计**。第一关资源说明也自称“对照阶段”，不是正式地编交付。本文可盘点与提出包装需求，但不能据此宣布三关或追踪行为已成为正式范围。若创作者要把整套三关作为正式资源版本交付，须先由 Architecture 与创作者确定版本边界，再同步正式来源；Art 不应以未审定代码反推玩法。

本次用户给出的《赛菲利亚》截图仅用于比较像素层次、角色/物件轮廓、UI 字形层级、边缘场景密度和动作反馈，**不授权复制其角色、UI、场景或玩法**。本项目仍遵守 GDD 的暗黑幻想、像素风、俯视角，以及“一刀决定结果”的信息优先级。

当前画面基线另见 `output/visual_audit_menu.png`、`output/visual_audit_failure.png`、`output/visual_audit_victory.png`：菜单确为大面积纯暗底加默认矩形按钮，胜败为普通中央弹窗。失败图中的弹窗遮住了战场中央和部分目标关系，说明“仍有 N 个存活”目前主要靠文案而非画面直接复核；这些截图是本轮视觉审计证据，不证明完整运行流程或试玩体验。

## 1. 玩家体验与优先级

首次玩家应在 960×540 固定视口内依次读到：我控制哪只狐狸、可走边界与目标是谁、还有一次刀、按住/取消/松开的差别、当前刀型及真实覆盖、斩后不能补救、哪些敌人死亡、为何胜败、如何重试或继续。包装应让“观察—确认—不可逆一刀—见证结果”有起伏，但不能用光效、文字或场景细节制造错误的碰撞、交互、敌人威胁或命中预期。功能自动测试通过不证明动态品质、首次可读性或好玩。

**P0**：信息真值或正式资源可生产性的阻断项；**P1**：跨画面一致性和明显的情绪/动作缺口；**P2**：前两项成立后的扩充。优先级不把未经确认的新玩法变成版本承诺。

## 3. 正式资源包与未决决策

先形成可复用的生产规范，再铺量：原生像素密度与比例、色板/明度阶、角色锚点与朝向、逐帧动作与事件点、Tile/Prop/遮挡分层、光源与条件性水域 mask、UI 中文字体/字形层级、图标/按钮状态、特效和音频时点、可编辑源文件及导出件。整幅缩放底图、整页图集截图或单帧“假动态”影子都不能单独称为正式资源。

建议先做**第一关视觉垂直样例**：可编辑庭院地编、狐狸/士兵动作一套、动态光影和浅水反射区、观察—双刀型瞄准—斩击—胜败完整一轮。随后扩展共用菜单/HUD/结算包及二三关的专属地编。用户已确认这轮覆盖当前可运行的三关，但不能以二三关仅换色或共用一张重复地砖图宣称正式资源已齐。

仍须回 Architecture/创作者决定：三关与追踪敌人何时进入正式 GDD 版本（与本轮美术覆盖范围不同）；正式审美方向和标题字；是否强化胜败演出；玩家并非狐狸本人的叙事假设是否要在外围表达。浅水纯视觉、角色照常走过且进入后动态倒影已获本轮确认。Art 的造型或 UI 提案若改变输入权限、可见信息、判定理解或关卡范围，须先评审，不能让已完成素材倒推规则。不能借参考图补出对话、商店、生命值、地图、道具等未实现系统。

## 4. 验收

| 检查 | 通过条件 | 不能替代它的证据 |
| --- | --- | --- |
| 可编辑性 | 改地面格、墙角、装饰位置、角色/敌人编排后，画面、遮挡与既有碰撞仍一致；源文件、切片、Tile/Prop/光影层可定位复用 | 一张 AI 背景或单张完整截图 |
| 水与动态光影 | 角色进出已确认的纯视觉浅水区、移动、转向、两刀型执行时，倒影在连续视频中合理变化；接地阴影与投影响应光向和动作；碰撞、斩击不变 | 预画亮斑、固定多边形跟随平移、单帧截图 |
| 规则可读 | 未知规则玩家出刀前能指出当前刀型、覆盖与可取消边界；出刀后能指出幸存者及胜败原因，不需要调试标签 | 开发者读代码或 HUD 数字能解释 |
| 表现与真值 | 预览与命中集合一致；装饰不暗示伪碰撞/伪交互；无攻击敌人不出现攻击预告；动效不遮挡幸存者与重试入口 | 功能自动测试通过 |
| 正式体系 | 菜单、关卡、角色、动作、FX、UI、中文文字在原生比例及不同屏幕比例下统一；所有交互状态可见 | 只完成第一关背景，其余仍是默认控件 |
| 情绪目标 | 创作者与至少一名未知规则玩家实玩后，记录是否感到决定性、是否辨别失误、是否愿意重试；争议项继续待验证 | “更精美”即视为好玩 |

验收素材应覆盖菜单焦点、每关观察、近弧/远直与跨界、取消、两种斩击、全灭/部分命中/挥空、胜败/重试，以及亮斑区内外和不同光照相位；**水与影子必须另有连续视频**。样例标注场景、屏幕尺寸、参数、Build 与资源版本。体验结论进相应正式版本 Test Log；本文不替代它。
