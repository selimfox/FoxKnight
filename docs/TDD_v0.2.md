## 0. 依据、状态与边界

本文件只细化 GDD v0.2 已确认范围的实现约束，不定义玩法。GDD 第 8 节仍是未决项来源；本文的状态名、模块名、公式和拟建路径均为技术计划，不表示文件、节点或功能已经存在，也不授权绕过制作前确认。

本次由 Architecture 完成 GDD 升版后同步技术文档；保留 [TDD v0.1](TDD_v0.1.md) 原文作为历史基线。旧文档的实现和测试结论不继承为 v0.2 证据。当前没有 v0.2 游戏运行、功能验收或体验结论。

以下结构采用 Godot 现有 2D 节点、GDScript、局部信号和 Inspector 参数，为 **v0.2 临时技术计划，不代表最终设计或已验证实现**。不建设通用能力系统、物理沙盒、事件总线、配置数据库或新编辑器。排除项遵守 GDD 第 7 节，尤其不加入时间回溯、尸体分叉、反弹或第二次改向。

## 1. 工程现状与迁移约束

只读核查的现状如下，与计划严格区分：

- 根目录 `project.godot` 已存在，记录 Godot 4.7 / Forward Plus，主入口为 `res://scenes/prototype/campaign.tscn`，窗口基准 960×540。项目继续使用该根工程，不建立嵌套的第二个 Godot 工程；此次不切换主场景或渲染后端。
- 旧 `scripts/actors/player_controller.gd` 为平面四向移动；关闭输入时会停止物理更新。新横版不能直接复用此锁定方式。
- 旧 `scripts/actors/enemy_controller.gd` 为 FLOATING 平面追踪、通过 TileArena 寻路；命中后禁用碰撞并释放对象。它不能直接承担新 A 的持续弹体生命周期。旧 TDD 的往返巡逻描述是历史内容，不作为新敌人行为决定。
- 旧 `scripts/combat/prototype_slash.gd` 查询直斩矩形后 Tween 修改玩家位置；不构成横版逐步冲击或真实首次接触检测。
- 旧 HUD、角色动画和反馈绑定俯视资源。保留旧场景及资源路径，不批量移动、删除或重命名；新白模使用独立表现入口。
- `scripts/cloud/check.sh` 调用旧验收运行器；`export_presets.cfg` 使用 `all_resources`，产品描述仍为 v0.1。新 Demo 实现后需明确新验收入口、主场景与导出范围，不能将旧检查通过当作新版通过。

可沿用场景组合、局部信号、目标登记、幂等结算及重试的技术思路；不直接复制旧状态机、双刀型、平面寻路、死亡删除流程或旧美术依赖。新全局类名采用 Sideview 前缀，避免与旧 `PlayerController`、`EnemyController` 等冲突。

`scenes/sideview/`、`scripts/sideview/`、`assets/sideview/`、`tests/sideview/` 已由主控建立目录骨架，仅含 `.gitkeep`。下列具体文件、子目录和运行内容仍为计划，不是现有资产清单；待设计敲定、相关制作前未决项确认后再创建：

| 路径 | 计划用途 |
| --- | --- |
| `scenes/sideview/sideview_demo.tscn` | 单个可重试白模入口、手工摆放平台与目标 |
| `scenes/sideview/actors/` | 狐狸与目标基础场景、可替换 Visual 子树 |
| `scenes/sideview/ui/` | 箭头、HUD 与重试界面 |
| `scripts/sideview/` | Demo 控制器、运动、冲击、目标/弹体、箭头和表现脚本 |
| `assets/sideview/` | 本 Demo 如需文件资源时的占位资源；不要求先制作正式资源 |
| `tests/sideview/` | 新版轻量验收入口与确定性布置；不套用旧 P/AC 编号 |

拟建根节点 `SideviewDemo (Node2D)` 组合以下职责：

| 部分 | Godot 节点基础 / 责任 |
| --- | --- |
| World | `Node2D` 下的 `StaticBody2D` + `CollisionShape2D`；平台、地面和墙 |
| Fox | `CharacterBody2D` + 独立 Visual / CollisionShape2D；左右、跳跃和既有冲击运动 |
| Targets | 手工摆放的静止目标实例，以 `Node2D` 配合 `Area2D` / `CollisionShape2D` 提供可查询受击区域；不巡逻、不攻击狐狸、不物理阻挡 A |
| A 的弹体运动 | 独立运动/伤害职责，以 `CharacterBody2D`、形状扫掠查询表达受重力影响的可控运动；不是通用刚体模拟框架 |
| AimOverlay / HUD | `CanvasLayer` + `Control` / `Line2D` 等中性表现；接收状态快照、转发一次确认 |
| CameraRig | `Node2D` + `Camera2D`；聚焦、恢复和震动，仅影响显示 |
| DemoController | 一个局部控制器拥有尝试状态、攻击提交、A 标识、目标存活集合与最终结果 |

A 可以在目标实例中切换为弹体职责，或以同一目标 ID 交接给专用节点；这是局部实现选择。交接必须保持位置、速度、碰撞状态与唯一身份连续，不能生成第二具 A 或重复发出死亡事件。普通死亡目标不获得该职责。

Visual、碰撞体、伤害查询分开；Inspector 或场景引用替换表现。箭头尺寸、角色贴图、镜头缩放不得成为碰撞或伤害真值。白模分别标识狐狸、活目标、A 和普通死亡目标。

## 3. 数据所有权与流程计划

| 所有者 | 拥有的数据与输出 |
| --- | --- |
| DemoController | `attempt_id`、攻击是否提交、首次目标 A、一次改向是否已提交、目标存活集合、伤害是否仍可能发生、结算是否已提交 |
| Fox 运动 | 位置、运动速度、跳跃消耗、提交方向、冲击进度；输入许可与物理更新许可分离 |
| 冲击检测 | 本次冲击路径、有效命中候选与首次接触证据；A 的选取规则等待 SV-OQ-02 |
| A 运动/伤害 | A 的目标 ID、打击分量、其余运动分量、初始受力方向、是否伤害有效、已伤害目标 ID 集合 |
| 箭头 | 待提交单位方向、初始受力侧锚点、显示与输入映射；不拥有伤害真值 |
| 镜头 / HUD | 消费状态与目标引用，不写入 A 的物理状态、命中集合或胜败 |

计划状态如下；只表达确认过的主路径，不补全未决分支：

| 状态 | 技术约束 / 合法主路径 |
| --- | --- |
| INITIALIZING | 恢复正常时间，登记目标，初始化一次攻击与镜头；完成后进入 PREPARING |
| PREPARING | 接收左右、跳跃与方向输入；合法 X 提交原子消耗攻击，进入 IMPACTING |
| IMPACTING | 禁止新的移动/跳跃/攻击，物理与已提交冲击继续；实际首击确定 A 后进入 REDIRECTING |
| REDIRECTING | 世界 0.02 倍运动，狐狸与 A 不冻结；实时显示箭头并允许一次左键提交；确认后进入 SIMULATING |
| SIMULATING | 正常世界速度；禁止新战斗输入与再次改向，等待有效伤害结束或全灭 |
| RESOLVED | 幂等显示结果，重试/离开；清理必须先恢复正常时间 |

首击登记、A 死亡转弹体、初始打击施加、慢速启用和状态发布必须在同一受控事件中完成，避免两个命中回调各创建一个 A。按键连发、鼠标重复事件、旧回调不能再次消耗攻击、再次确认或重复结算。

IMPACTING 未命中如何结束、同帧多目标如何选 A、REDIRECTING 中 A 提前停止的退出方式，均不在此状态表中暗设默认分支，分别受 SV-OQ-02～05 阻塞。全灭与确认状态退出的先后若涉及调整期事件，也按 SV-OQ-03 确认后落实。

## 4. 运动、时间与改向

### 4.1 输入与冲击

默认映射在根 `project.godot` 的 InputMap 公开：WASD 方向、Space 跳跃、X 攻击，左键用于首次命中后的确认；脚本读取动作名，不按物理键码硬编码。左右控制与冲击方向采样分离，组合方向归一化，避免斜向意外提高基础速度。无方向输入的提交、冲击结束与二段跳恢复规则等待 SV-OQ-04。

Fox 使用真实物理步和碰撞更新，不用 Tween 直接写位置代替冲击。关闭输入只阻止新意图，不清零速度、不提前返回整个物理更新；慢速期间也更新既有冲击与已确认的重力运动。冲击期间各运动的具体组合与结束条件须服从 GDD 及 SV-OQ-04，不从旧控制器继承。

### 4.2 世界与实时表现

计划由 DemoController 独占本 Demo 的世界时间倍率；首击启用 `Engine.time_scale = 0.02`，确认后恢复 `1.0`。物理运动只使用世界缩放后的时间步一次，不能再额外乘 0.02，也不能用暂停树把 A 或狐狸冻结。

箭头输入、HUD、镜头聚焦/恢复与震动使用独立于世界缩放的实时时间差和输入事件。实时时间差由单调时钟记录，不依赖将世界 delta 除以倍率，避免恢复瞬间的跳变。`CanvasLayer` 本身不保证计时独立；相关插值、Tween、计时器和动画必须逐一明确时钟，不能直接复用旧缩放计时流程。此方案尚未在运行中验证。

慢速必须有明确状态文本或标记。世界倍率、实时累计、物理时间、狐狸/A 位置和状态切换进入验证日志；稳定慢速区间测量世界累计时间 / 实际经过时间为 0.02，记录采样起止、区间及计时误差，排除切入/恢复边界干扰。同时比较狐狸/A 的位置变化证明对象未冻结；仅看倍率显示或慢动作画面不能证明计时正确。

### 4.3 仅旋转打击分量

在 A 接受本次唯一打击时，分开记录固定强度 `J`、初始单位方向 `d0`、打击造成的速度分量 `v_hit` 与剩余运动 `v_other`。这里 `J` 表示同一基础打击转换后的速度增量大小；不是新增质量或装备系统。初次施加一次 `v_hit = J * d0`，总运动由 `v_hit + v_other` 组成；重力在世界物理步中更新 `v_other`。

在合法确认时，将已有 `v_hit` 替换为 `J * d_confirmed`，保留确认时的 `v_other`。不得执行“当前总速度再加一次 J”，也不得把总速度整体归一化为 J、清空竖直速度或重新设置重力。确认前已产生的位移与重力积累不回退；确认后强度与全局重力不变。速度分解应可直接记录和断言，不从已混合总速度中猜测重力贡献。

若 A 已接触世界或失效，不能套用该公式暗自恢复弹体伤害；合法确认条件与退出顺序受 SV-OQ-03 阻塞。此处不选择自动确认、取消、超时或重新发射。

### 4.4 箭尾与镜头输入一致性

首击保存初始受力方向 `d0`。箭尾由 A 的碰撞/占位几何在该方向侧的边缘位置计算，随 A 平移；鼠标旋转待提交方向时不旋转受力侧锚点。箭尾只是视觉锚点，不移动 A 或另设生成点，不绘制重力抛物线或完整连锁预测。

屏幕输入与世界方向之间使用显式坐标映射；镜头平移、缩放、震动和 A 的锚点移动不得通过每帧无补偿的“当前世界鼠标减箭尾”改写已选方向。记录并补偿显示变换，保留鼠标未移动时的选择；真实鼠标调整后更新待提交方向。输入和渲染消费同一份方向快照，左键原子提交最后可见方向，不能在确认回调内用另一套镜头变换重新算一次。

镜头由独立 Rig 跟踪 A，聚焦、震动、恢复叠加在表现变换中，不移动碰撞体。进入/恢复时长、幅度通过 Inspector 调整；中心/边缘首击与静止鼠标验收后才能确认可读性，不能在文档中宣称聚焦效果已成立。

## 5. A 的碰撞、去重与结算

### 5.1 单 A 生命周期

A 首击即从存活目标集合移除一次，进入唯一弹体伤害身份；不等待左键才开始运动。其后伤害其他活目标时逐目标登记 ID，仅发出一次死亡；A 穿透普通 B/C 继续运动，普通目标不物理阻挡、反弹或偏折 A。B/C 不转为弹体、不继承打击分量、不重入 REDIRECTING。表现节点释放与目标死亡真值分离，不能靠节点消失计数。

A 撞墙或落地，立即关闭后续伤害，不反弹。物理接触、伤害关闭、碰撞事件在同一受控顺序内处理，不能让表现延迟延长伤害。确认前普通命中的处理时点、A 提前接触世界后的改向退出与同帧歧义，按 SV-OQ-02/03 澄清，不默认吞事件或自动提交。

### 5.2 高速检测

冲击首击与 A 运动均记录上一个和当前物理位置，对实际移动段进行带体积的扫掠；不只依赖终点重叠或单个 Area2D 进入信号。使用 Godot 2D 形状运动查询/分段检测等可替换方案，记录实际接触位置、沿段次序、世界截断点和目标 ID。

A 在碰到世界前的移动段中可能经过多个目标：必须收集路径上的有效命中并去重，不能因首次命中 B 就停止其继续运动，也不能命中墙后方的目标。目标层与世界层分开查询/分类，过滤 Fox、自身和普通尸体；普通目标仅参加伤害查询，不参与 A 的物理阻挡或偏折。扫掠不得扩张伤害形状作为漏判补丁。本版目标按已确认的静止布置检测，不建设移动敌人预测。

只保证检测顺序可记录、可复现，不用查询数组顺序选择 A。几何并列首触、与世界同点接触若改变规则结果，必须交回 architecture，不能用实例 ID 或任意优先级悄悄补设计。高速方案在正常/慢速/切换瞬间、窄目标、多目标和墙前后场景验收前保持未验证状态。

### 5.3 有效伤害结束与结果

存活集合为空时胜利真值只能提交一次；仍有目标时，需确认没有仍有效的直接斩击或 A 伤害过程，才能提交失败。不能沿用旧“斩击 finished + 固定等待时间”判失败。是否存在首击后的直接斩击伤害由 SV-OQ-02 决定，不能先按不存在实现。

伤害有效标志与动画、音效、镜头时长分离。A 碰墙/落地后的伤害关闭已确认；空挥、Fox/A 落出关卡、冲击结束和调整态退出等结束来源分别等待 SV-OQ-03～05。禁止用未确认的固定超时、补充角色死亡或生命值规则让流程看似闭合。

## 6. 重试与全局清理

HUD 在慢速、演算与结算阶段保留重试入口，重试由 DemoController 统一处理。重载/重建场景前先取消旧尝试回调、恢复 `Engine.time_scale = 1.0`，清理聚焦/震动/箭头和输入快照；新尝试重新登记对象与位置、攻击一次、A 空引用、目标集合、去重集合及跳跃/冲击状态。

全局时间不会仅因场景重载自动成为可信初值。初始化、重试、离开 Demo 和异常清理均须恢复正常倍率；旧尝试的延时回调通过 `attempt_id` 等局部有效性校验失效，不能在新场景重启慢速、显示旧结果或再扣攻击。镜头需恢复位置、缩放、偏移及实时插值累计。不得把全局倍率恢复寄托于死亡动画完成。

## 7. 参数、验证与验收映射

参数使用局部 Inspector 入口，所有权清楚：Fox 拥有移动/跳跃/冲击运动参数，A 运动拥有打击强度/重力，DemoController 拥有慢速倍率，箭头/CameraRig 各自拥有表现参数。提交时保存本次使用值，避免执行期间参数来源漂移；不创建通用配置数据库。GDD §4.3 范围外的规则参数不得借调参名义引入。
