## 0. 目的与边界

本文说明如何实现 GDD v0.2 已确认范围，不重新定义玩法。发生冲突时以 `docs/GDD.md` 为准。

v0.2 在保留 v0.1 操作和双刀型回归基线的同时，新增：可配置三关 Campaign、共享次数的战前地形与敌人拖动、关卡内多 TerrainGrid 自动聚合、动态可移动范围、步兵追踪、弓箭手远程威胁、狐狸一击死亡、提交斩击后的结算期伤害免疫、关间 UI 与返回主界面。

不建立自研关卡编辑器、通用 AI 框架、技能系统、存档、成长、掩体或正式内容管线。默认三关是可替换的 Prototype 内容，不代表创作者已确认最终编排。

## 1. 技术原则

- 保留 `scenes/prototype/prototype_level.tscn` 与现有 v0.1 验收入口，作为双刀型回归基线；v0.2 使用独立场景与脚本，避免破坏已结算证据。
- `project.godot` 的主场景切换为 v0.2 Campaign。Campaign 在单一根节点内加载和释放关卡，避免为 Prototype 引入 Autoload 或持久化存档。
- 三关分别保存为普通 Godot 场景。地形格、狐狸、敌人和导出参数均可在编辑器中调整，不制作专用编辑器。Level 递归发现本场景的 TerrainGrid、TerrainCell、狐狸与敌人，不维护手工注册数组。
- 动态地形使用离散四邻接网格作为移动真值；玩家表现仍是连续移动，敌人沿网格路径连续移动。
- 视觉、移动合法性、寻路和直斩截止距离共用同一个地形占用数据，避免画面与规则分离。
- 敌人行为保持局部、可替换。步兵与弓箭手共享最少的生存和地形移动能力，但不建立行为树或通用能力系统。
- 功能验收与人工体验验收分开。自动化不声明趣味性、策略性或一刀价值成立。

## 3. Scene 职责

### 3.1 Campaign

`prototype_campaign.tscn` 包含：

- `CampaignController`：持有 `Array[PackedScene]` 关卡顺序和当前索引。
- `LevelHost`：同一时刻只承载一个 v0.2 关卡。
- `MainMenu`：开始游戏入口。
- `CampaignResult`：最终胜利与返回主界面。

Campaign 监听关卡的 `level_won`、`retry_requested` 和 `main_menu_requested`。切关前先释放当前关卡及其箭矢、Tween、Timer 和信号，再实例化下一关。关卡不直接修改 Campaign 索引。

### 3.2 v0.2 Level

每个 `level_XX.tscn` 使用相同结构：

```text
V02Level [level_controller.gd]
├── Backdrop                       # 中性虚空底色
├── TerrainGrid* [terrain_grid.gd] # 可复制的编辑预制块，数量不限
│   └── Cells                      # TerrainCell 场景实例，可在 Godot 中摆放
├── Actors
│   ├── Player                     # 复用 player.tscn
│   └── Enemies                    # Infantry / Archer 场景实例
├── Projectiles
├── Effects
├── FixedCamera
├── FeedbackController
└── HUD
```

关卡场景直接定义：一个或多个 TerrainGrid 预制块及其地形格、狐狸与敌人位置、敌人实例类型、调整次数及各敌人行为参数。Level 负责自动遍历、聚合地图、共享战前调整状态和结算，不保存跨关进度。

### 3.3 TerrainGrid 与 TerrainCell

`TerrainCell` 是一个可视、可命中的单格组件。每个 `TerrainGrid` 只承担可复制的编辑分组；Level 初始化时递归收集全部 TerrainGrid 的 TerrainCell，并由一个关卡级地形协调对象建立 `Dictionary[Vector2i, TerrainCell]` 作为唯一运行真值。坐标换算使用统一 `cell_size`，网格原点根据全部地块载入后的最终世界位置自动推导，不以任一预制块的局部边界或可编辑固定原点为运行真值。协调对象提供：

- 世界坐标与格坐标转换。
- 查询世界位置是否可行走。
- 四邻接路径搜索。
- 地形与敌人鼠标拖动的开始、预览、提交与回滚；鼠标命中敌人时优先选择敌人，否则选择地形。
- 两类操作共享的调整次数与混合历史栈、逐步撤回和次数返还。
- 移动后连通性、占用和边界合法性检查。
- 沿方向取得直斩可行走截止距离。

地形合法移动把一个未占用格移到关卡聚合网格边界内的空格，并保持所有角色位于地形上；PREPARING 中间状态不检查整体连通，可以保持或增加连通分量。敌人合法移动只接受目标为现有未占用地形，不限制距离，无需验证中间可行走路径，也不受当前连通分量限制。狐狸不可拖动，敌人脚下地形不可拖动。非法释放恢复原位且不扣次数。

Level 持有唯一 `remaining_adjustments` 与 `Array[AdjustmentRecord]`。记录带操作类型、对象引用、来源格和目标格；撤回按栈顺序原子恢复最近一次地形或敌人操作并返还一次次数。次数为零时拒绝新拖动但允许撤回。进入战斗时清空历史并禁用两类拖动。调整次数由 Level 导出参数提供。

Level 分别维护 `structure_valid` 与 `battle_ready`。`structure_valid` 由有效地面、统一尺寸、自动映射后的边界与重复坐标、角色初始占地决定；编辑位置偏差和多个独立区域不影响结构有效性。`battle_ready` 只要求结构有效且当前没有正在拖动的对象，不检查全地图连通。地形提交或撤回后刷新状态；开始战斗时再次校验 `battle_ready=true`。

聚合器先取得所有 TerrainCell 的最终 `global_position`，分别搜索 X/Y 轴上最小化最大吸附误差的网格相位，再在 `grid_bounds` 内选择最接近内部画面锚点的整数偏移，得到本次运行的 `grid_origin`。因此移动 Level、TerrainGrid、中间父节点或单个 TerrainCell 后都会重新计算；Inspector 不再暴露需要作者维护的原点或容差参数。任何位置偏差都只登记一次汇总开发警告并映射运行实例，不改写 `.tscn`。自动映射后的重复坐标、越界与不同 `cell_size` 属于结构错误；错误详情只写开发日志，不调用 HUD 技术错误界面。独立区域数量不记录为错误或警告。

聚合器在吸附地块前记录“作者位置 → 运行格点”的映射。角色若位于某个作者地块范围内，则应用同一平移并保留其相对地块的偏移；随后再使用角色占地圆检查其完整落在聚合地形内，并检查初始角色之间不重叠。敌人拖动提交后吸附目标格心，但历史记录额外保存拖动开始前的实际运行位置，撤回恢复该位置。移动、敌人寻路、占地查询、直斩截止与拖动合法性都只读取自动映射后的聚合字典和位置真值。路径搜索返回空路径是多个独立区域下的正常结果；敌人保持原位，不回退为朝目标直线穿越虚空。

视觉节点可以在 TerrainCell 内使用非方形贴图、圆角、缩放或装饰轮廓，但逻辑根节点不通过旋转或非统一缩放改变单格占地。v0.2 不建立任意多边形导航或基于像素边缘的自动连通。

战前状态下 TerrainCell 不再绘制中心点。可拖且未被角色占用的格使用区别于战斗地面的准备色，并由统一时间函数驱动低频边框/亮度呼吸；地形悬停时增强绿色。敌人悬停时保留角色轮廓并增加橙紫色描边。非法对象或目标使用红色即时反馈。拖敌人时高亮聚合地图内全部现有空地，拖地形时高亮聚合边界内的空网格目标。HUD 同时显示当前选择语义、合法性、次数与撤回按钮状态。开始战斗后停止准备反馈并恢复普通表现。

### 3.4 步兵

步兵场景暴露 `move_speed`、`detection_radius`。未发现狐狸时保持原位；首次进入探测范围后锁定发现状态，使用 TerrainGrid 的四邻接路径持续趋近。接触狐狸时请求 Level 结算玩家死亡。步兵仅有接触伤害。

### 3.5 弓箭手

弓箭手场景暴露 `move_speed`、`detection_radius`、`preferred_min_distance`、`preferred_max_distance`、`windup_duration`、`attack_interval` 和 `arrow_speed`。

发现规则与步兵相同。过近时选择增加距离的可达相邻格，过远时沿路径接近，位于理想距离区间时停止。无法远离时停止移动但仍可攻击。攻击开始时记录朝向狐狸的方向并显示前摇线，前摇结束后沿固定方向生成不追踪箭矢。箭矢不被基础地形或虚空阻挡，只在离开场景边界、命中狐狸或关卡结算时销毁。

## 4. 状态与数据流

### 4.1 Level 状态

```gdscript
enum RoundState {
    INITIALIZING,
    PREPARING,
    OBSERVING,
    AIMING,
    EXECUTING,
    RESOLVED,
}
```

| 状态 | 允许行为 | 敌人/伤害 |
| --- | --- | --- |
| `INITIALIZING` | 无 | 停止 |
| `PREPARING` | 拖动地形或敌人、混合撤回、确认开始、返回主界面 | 停止；无伤害 |
| `OBSERVING` | WASD 移动、开始瞄准 | 运行；可致死 |
| `AIMING` | 移动、调整刀型、取消或提交 | 运行；可致死 |
| `EXECUTING` | 无输入 | 运行表现；玩家免疫敌人伤害 |
| `RESOLVED` | 重试、下一关或返回主界面 | 全部停止 |

### 4.2 玩家死亡与斩击提交竞争

- Level 是生死与结果的唯一裁决者。
- 敌人和箭矢只发出伤害请求，不直接切场景。
- 只有 `OBSERVING` 或 `AIMING` 状态接受玩家死亡。
- 有效斩击提交先原子地切换到 `EXECUTING`，再创建斩击；此后所有伤害请求被忽略，直到结果锁定。
- 若死亡请求先被 Level 接受并进入 `RESOLVED`，随后到达的鼠标释放不得提交斩击。
- 直斩和圆斩使用同一规则。

### 4.3 重试与跨关

- Level 在进入时保存由场景定义的初始状态；重试通过 Campaign 重新实例化同一 PackedScene，天然恢复地形、角色、敌人、次数和唯一一刀。
- 失败 UI 只显示重试与返回主界面。
- 非最终关胜利 UI 显示下一关与返回主界面；最终关由 Campaign 显示整体胜利。
- 返回主界面时释放当前 Level，重置索引为 0。

## 5. Player 与斩击兼容修改

- `PlayerController` 增加可选 TerrainGrid 引用和 `is_damage_immune` 状态，但保持 v0.1 场景未绑定 TerrainGrid 时的原移动行为。
- v0.2 移动尝试由 TerrainGrid 验证角色占地圆是否完全落在可行走区域。优先按完整位移尝试，失败时分别尝试 X/Y 分量以保留贴边滑动。
- `PrototypeLevel` v0.1 仍使用矩形 Arena 裁剪。
- v0.2 Level 使用 TerrainGrid 计算直斩允许距离，并把同一距离传给预览和 `PrototypeSlash`。直斩在首个不可行走边界前停止。
- 斩击本身不判断玩家无敌；Level 的伤害请求入口依据状态裁决，避免多个攻击来源复制免疫逻辑。

## 6. 场景视觉清理

旧 `prototype_level.tscn` 中下列节点没有碰撞、状态或交互语义，并可能误导 v0.2 地形判断：`ArtTiles/FloorA-E`、`ArtTiles/WallA-C`、`CenterPath`、`RuneA/B`、`RoomLabel`。从当前运行场景清理这些元素，并移除不再使用的场景资源引用。

`Backdrop` 保留为中性虚空底色。v0.2 不使用覆盖全场的 `Floor/FloorInset`；实际 TerrainCell 是唯一地面视觉真值。v0.1 的 `Boundaries` 碰撞和有意义的角色、攻击、反馈节点不得随背景清理删除。

v0.2 步兵与弓箭手使用不同 AtlasTexture 区域或独立纹理；步兵保持重甲、盾牌和近战武器轮廓，弓箭手保持兜帽、弓和箭袋轮廓。两者可以复用生存与状态脚本，但不得复用同一静态角色图像。Prototype 阶段允许同一角色的 idle、walk、hit、death 槽位暂时引用同一角色纹理，由现有受击与死亡特效补足状态变化。

## 7. 开发顺序

1. 清理无语义场景装饰，保持 v0.1 Smoke Acceptance 通过。
2. 建立 TerrainCell/TerrainGrid、拖动、连通检查、战前视觉状态和玩家移动约束。
3. 建立 v0.2 Level 状态、致死结算、提交后免疫和重试/主界面流程。
4. 实现步兵及其可调参数，验证探测、持续追踪、路径和接触死亡。
5. 实现弓箭手与箭矢，验证距离带、前摇、方向锁定和致死命中。
6. 建立 Campaign、三关配置、下一关及最终胜利流程。
7. 摆放一组默认三关，进行自动验收、实际窗口试玩和可读性修正。

## 9. 技术风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 多个预制地形块各自成为孤立运行地图 | Level 自动聚合全部 TerrainGrid；移动、路径、位置合法性与直斩截止共用关卡级字典 |
| 自动推导把差异过大的地块映射到意外格位 | 记录作者位置到运行格点的汇总 warning；重复映射、越界和格尺寸问题继续阻断调整与开战；Acceptance Runner 覆盖 Level、Grid、单格与角色的混合编辑变换 |
| 多个合法区域被全局连通检查误判 | 连通只用于局部寻路；聚合地图允许任意数量区域，Start 不检查分量数 |
| 一格通道视觉可走但角色半径卡住 | 地形格尺寸与角色占地半径建立明确余量，并加入窄通道验收 |
| 敌人与狐狸位于不同区域时穿越虚空 | 空路径视为合法的不可达结果；敌人停止移动，弓箭手仍按既有远程攻击规则运行 |
| 混合撤回后字典、角色位置与次数不同步 | Level 历史记录保存类型、对象、来源与目标；撤回作为单一原子操作并加入交错操作验收 |
| 直接移动敌人形成战前唯一解 | 不添加隐藏限制；记录玩家是否优先排敌与开战后是否仍需决策，交给关卡编排和试玩裁决 |
| 死亡与斩击同帧竞争 | Level 状态先行裁决；EXECUTING 忽略伤害，RESOLVED 拒绝提交 |
| 弓箭手在距离边界抖动 | 使用最小/最大距离带，不使用单一阈值；无法移动时保持位置 |
| 切关后旧箭矢或 Timer 回调污染新关 | 箭矢归属 Level；Campaign 切关时整体释放并只监听当前实例 |
| 默认三关被误当作最终关卡设计 | 参数与节点全部场景可编辑；文档和 Test Log 明确其占位状态 |
| 圆斩成为所有关卡支配解 | 默认关卡只作为诊断材料；人工试玩记录刀型选择与退化策略，不用自动通关宣称解决 |
