## 1. 游戏定位与核心体验

### 1.1 一句话概念 [已确认]

一个只能挥出一刀的狐狸骑士，通过观察战场、规划行动与调整自身位置，在不可逆的攻击中决定战斗结果。

v0.1 以最小形式验证这一概念：玩家在清楚可读的俯视战场中直接控制狐狸移动和站位，选择唯一一次出刀；刀落之后，战斗控制结束，系统自动演算并结算结果。

### 1.2 类型与核心反转 [已确认]

- 游戏类型为 2D 动作解谜游戏，结合动作游戏的打击反馈、解谜游戏的观察与推理，以及战术游戏的行动规划。
- 核心反转是弱化传统动作游戏的连续攻击与持续输出，强调理解世界、规划行动，并通过一次不可逆的攻击改变结果。
- “反传统 ARPG”是项目方向，不代表 v0.1 需要建立完整 ARPG 系统后再进行反转。

### 1.3 设计支柱

| 支柱 | 玩家感受 | v0.1 设计含义 |
| --- | --- | --- |
| 一次攻击，改变结果 | 攻击是决定，而不是循环消耗 | 唯一攻击；没有普通攻击；出刀后不能补救 |
| 观察胜过操作 | 理解规律、环境与解法比反应速度或连招更重要 | 敌人行为与战场信息清楚；操作门槛较低 |
| 理解与准备带来爆发 | 通过观察世界、调整条件，创造决定性的攻击机会 | 以移动和站位承担最小准备过程；一刀提供强烈的视觉与情绪反馈 |
| 每一次行动都有重量 | 移动、交互和攻击都可能影响最终结果 | v0.1 先验证移动、站位、时机与唯一一刀；完整关卡交互暂不实现 |

核心体验链路为：

> 观察与规划 → 行动决策 → 一刀结果反馈

### 1.4 核心体验假设 [待验证]

- H1：唯一一次攻击机会能够产生有趣的站位与时机决策。
- H2：若前置信息足够清楚，出刀后失去控制会让玩家感到“确认选择并见证结果”，而不是“被剥夺操作”。
- H3：高质量的斩击反馈能够让玩家此前的理解与准备获得明确的视觉、听觉和情绪回报。
- H4：理解局面并用一次选择改变结果，可能成为长期方向；v0.1 只验证最基础的玩法形式，不确定最终主题。
- H5：在仍然只有一次攻击机会的前提下，以鼠标距离选择远距直线斩或近身弧形斩，能够增加空间表达与主动决策，而不会把“一刀”削弱为多技能循环或硬解谜的答案提交。

## 2. v0.1 原型验证目标

- 玩家能否迅速理解：可以移动、只有一刀、需要尽量一次解决所有敌人？
- 移动敌人是否让站位从静态找答案变为观察、预测与调整？
- 出刀后失去控制是否自然、清楚且令人期待？
- 斩击反馈是否足以回报此前的观察、规划与行动准备？
- 失败后玩家能否理解问题所在，并愿意立即重试？
- 更主观的感受：这个 Demo 是否好玩？是否具有可延展性？
- 两种可预览刀型能否减少“只能等待敌人共线”的单一解法，并把主动性集中在如何塑造和提交唯一一刀上？

v0.1 不验证完整世界观、商业定位、长期成长、关卡编排、Boss 战或重复游玩结构，也不追求高难反应、格挡和连招深度。具体不做的系统见第 8 节。

## 3. 核心玩法流程

### 3.1 玩家流程 [已确认]

| 阶段 | 玩家权限 | 系统行为 | 退出条件 |
| --- | --- | --- | --- |
| 进入关卡 | 无 / 短暂锁定 | 生成狐狸与敌人，显示主要战场信息 | 初始化完成 |
| 观察、规划与站位 | 移动、观察、调整位置、选择时机 | 敌人按简单规则移动 | 玩家按下鼠标左键进入瞄准 |
| 瞄准与调整 [待验证] | 保持移动；移动鼠标调整距离与方向；右键取消 | 根据狐狸到鼠标的距离实时选择并显示与有效判定一致的直线斩或弧形斩范围；敌人保持正常移动 | 松开左键提交，或右键取消 |
| 确认出刀 | 不再接受战斗输入 | 消耗唯一一刀；若提交弧形斩，在提交瞬间采样狐狸指向鼠标的方向，随后关闭战斗输入 | 攻击启动 |
| 自动演算 | 无控制权 | 完成斩击、命中、死亡和反馈 | 表现完成 |
| 结算 | 无战斗控制 | 统计目标敌人 | 0 个存活为胜利，否则失败 |
| 重试 / 离开 | 菜单输入 | 重置本关或退出 | 玩家选择 |

松开鼠标左键是 v0.1 刀型实验的攻击提交点。提交前可以移动和右键取消，且不消耗攻击机会；提交时根据鼠标距离确定刀型。弧形斩以狐狸指向鼠标的方向决定一次不可修正的短位移：鼠标位于可调方向死区圆内时原地斩击，位于死区外时按箭头所示方向短移。提交后玩家不能继续移动、转向、追加输入、取消或补救。未来是否允许执行期持续互动仍是未决问题，不属于 v0.1。

### 3.2 目标节奏 [待验证]

进入与读图（1–3 秒）→移动、观察与规划（5–20 秒）→一刀爆发（约 0.5–2 秒）→清楚结算（1–3 秒）→立即重试。中间阶段的具体情绪尚未定义；具体时长需要调试，不是锁定参数。

## 4. 系统规格

### 4.1 玩家角色与移动 [已确认]

- 使用可移动的狐狸骑士白模或占位表现。
- 采用 2D 俯视视角，移动平面与碰撞边界清楚。
- 提供基础方向移动，速度可调；不要求冲刺、翻滚、格挡或连击。
- 移动用于调整站位、改变斩击覆盖关系，并观察敌人是否形成合适位置。

操作层面，玩家在 v0.1 直接控制狐狸，这与叙事身份并不冲突。叙事层面已确认玩家并非直接扮演狐狸骑士；这种控制可能来自尚未确定的能力、身份或规则关系。v0.1 不解释该关系，也不建立叙事身份系统。

### 4.2 唯一一刀与双刀型实验 [已确认 / 待验证]

- 每次关卡尝试只能攻击一次，没有普通攻击。
- v0.1 刀型实验仍只消耗唯一一次攻击，但根据提交时狐狸与鼠标的距离选择两种临时斩击形态。该实验用于验证一刀内部的空间表达能否增加主动性，不代表正式技能系统或最终斩击形态。
- 当狐狸与鼠标的距离大于等于可调阈值时，执行既有远距直线位移斩；其方向、直线覆盖、边界截断和移动逻辑保持原实验规则。
- 当狐狸与鼠标的距离小于该阈值时，执行近身弧形斩。弧形斩以狐狸周围的 360 度圆形范围为基础，并以狐狸指向鼠标的方向决定短位移。鼠标位于可调方向死区圆外时，狐狸沿该方向完成一次可调的短距离位移，圆形有效范围和圆弧刀光在执行期间始终跟随狐狸；鼠标位于死区圆内时原地完成弧形斩。
- 弧形斩的瞄准指示始终只显示以狐狸当前位置为圆心的圆形范围，不使用胶囊形或其他合并路径轮廓。短位移路径不作为范围图形提前展开；执行时以跟随狐狸移动的圆形刀光持续说明当前能够命中的区域。
- 弧形斩瞄准指示内必须同时显示方向死区圆和实时位移箭头。死区圆以狐狸为圆心、半径可调；鼠标在死区外时，箭头从圆心指向鼠标，长度表示按场地边界裁剪后的实际短位移；鼠标进入死区时箭头隐藏，明确表示本次将原地斩击。
- 弧形斩必须使用区别于远距直线斩的狐狸动作和圆弧形刀光。角色动作、刀光与圆形命中范围需要在同一执行时段内同步，且表现不得扩大或缩小真实命中集合。
- 刀型距离阈值、弧形斩半径、弧形斩短位移距离和方向死区半径必须作为 Prototype 可调参数开放；方向死区半径默认值为 24，其余现有默认值保持不变。所有默认值只作为首轮测试起点，不是锁定设计。
- 基础小怪被有效命中后死亡。
- 出刀后玩家立即失去战斗控制。
- 系统完成斩击、命中、死亡和胜败结算。
- 重开关卡后恢复一次攻击机会。

- [待验证] v0.1 使用“按住鼠标左键瞄准、松开提交、瞄准时右键取消”的临时输入方案。瞄准期不锁定移动，不启用时间缩放；鼠标距离决定刀型，两种刀型的方向均由狐狸指向鼠标。WASD 只负责瞄准期移动狐狸，不再决定弧形斩提交后的位移方向。
- [待验证] 鼠标与狐狸重合或位于方向死区圆内时仍属于近身弧形斩，并明确提交为原地弧形斩，不因缺少位移方向而自动取消。

两种刀型都对基础小怪保持一击必杀，且共同消耗同一把唯一一刀。斩击的最终形状、移动方式、瞄准方法和输入方法仍未最终确定；上述方案只用于 v0.1 低成本验证主动性、操作清晰度与仪式感。v0.1 不建立支持多技能的通用框架，只保留这两种临时几何及其少量可调参数。

### 4.3 敌人 [已确认]

- 具备至少一种简单、可观察的移动行为。
- 初始位置、移动速度、移动方向或路径可调。
- 被有效命中后停止行为并死亡。
- 不主动攻击狐狸；不实现玩家生命值、狐狸受伤或死亡。
- 不实现护甲、技能、群体协作、元素反应等复杂状态。

移动方式可从固定方向、往返巡逻或趋近中选择一种，不要求同时支持全部类型。

### 4.4 镜头

- [已确认] 使用固定俯视相机，不常规跟随狐狸。
- [已确认] 不实现自由缩放、手动平移或常规跟随。
- [待验证] 是否需要完整、无裁切地显示整个关卡，需结合屏幕比例与可读性测试。
- [待验证] 斩击瞬间可测试短促震屏，但不能妨碍读取命中和存活信息。

镜头目标是让玩家尽可能清楚地理解主要战场信息。

### 4.5 胜败与重试 [已确认]

- 自动演算结束时，所有目标敌人死亡则胜利。
- 自动演算结束时，仍有目标敌人存活则失败。
- 结算需要清楚显示结果，并提供快速重试。

失败在世界观中的解释、狐狸是否会死亡均不属于已确认规格，见 OQ-06 与 OQ-12。

### 4.6 反馈与演出

| 层级 | 最低要求 [已确认] | 增强方向 [待验证] |
| --- | --- | --- |
| 预备 | 可攻击状态与朝向清楚 | 轻微蓄势姿态或音效 |
| 命中 | 受击与死亡状态清楚 | 命中停顿、残影或斩线 |
| 画面 | 斩击轨迹可读；弧形斩具有跟随狐狸的圆弧刀光与专属动作 | 短促震屏、瞬时对比或色闪 |
| 声音 | 挥刀、命中、结算三类反馈 | 环境收束、刀鸣与余响 |
| 结算 | 胜败与重试入口清楚 | 利落的镜头或节奏收束 |

## 5. 关卡与内容规格

### 5.1 首轮基础关卡 [已确认]

- 首轮只要求完成一个可重复开始的基础敌人关卡。
- 使用单场景、单房间和固定相机。
- 至少有一个狐狸出生点及多个可配置的敌人出生点。
- 边界或障碍只需满足移动与站位测试，不制作完整机关系统。
- 敌人移动应尽量不依赖文字教程也能理解。
- 狐狸移速、敌人位置与移动参数、临时斩击判定和基础反馈可调。

### 5.2 关卡原则 [待验证]

- 问题主要来自空间和时间关系，而不是高精度输入。
- 玩家在出刀前应获得足够信息；失败应更接近“我判断错了”，而不是“系统隐藏了规则”。
- 理想解应呈现一次干净、整体性的解决。
- 长期方向允许玩家通过移动、刀型、关卡组件或环境因素调整条件并创造出刀机会；v0.1 本轮先以移动、站位、敌人运动和两种可预览刀型验证这一原则，不制作完整关卡交互系统。关卡交互不得为了增加主动性而退化成固定站位、固定机关顺序或唯一答案的硬解谜；是否加入仍待后续单独验证。
- 基础关卡完成后，可复制 3–5 个少量参数变体用于比较；这些变体不是首轮验收要求。

### 5.3 视觉与主题方向

- [已确认] 视觉方向关键词：暗黑幻想、像素风格、俯视角。
- [已确认] 主题探索关键词：选择、后果、命运、道德困境、反传统 ARPG 体验。
- [待验证] v0.1 的美术首先服务于角色、敌人、边界、斩击与结果的可读性；不要求以正式美术资源验证最终风格完成度。
- [未决] 主题关键词如何进入具体剧情、关卡选择与“一刀”的意义，仍需后续设计，不由关键词直接推导世界观结论。

## 6. 信息、界面与可用性

- HUD 最低信息包括剩余攻击次数（1/0）、目标敌人状态和胜败结算。
- [待验证] 进入瞄准状态后必须显示当前将提交的刀型及其有效范围：远距直线斩显示方向、宽度与终点；近身弧形斩显示以狐狸当前位置为圆心的攻击圆、方向死区圆，以及死区外从圆心指向鼠标的实际短位移箭头，不显示短位移形成的胶囊形路径。狐狸移动、鼠标跨过刀型阈值、进入/离开死区或改变角度时，预览必须实时更新；弧形斩提交后的圆形刀光随狐狸短位移同步移动，负责说明执行中的即时命中区域。
- 敌人、狐狸、斩击轨迹和场地边界需要有足够对比。
- 震屏与闪光应可调，不能妨碍读取信息。
- 教程优先使用行动提示和首关构图，v0.1 不制作大量文字说明。

## 7. v0.1 功能需求与验收标准

只提供支持快速迭代的必要参数：狐狸移动速度；敌人初始位置、速度及移动方向或路径；直线斩距离与宽度；刀型距离阈值；弧形斩半径、短位移距离与方向死区半径；基础反馈强度与时点；结算等待时间和关卡重置。

本节是 GDD 交付给 TDD 的需求基线。功能需求说明“系统必须具备什么行为”，验收标准说明“在什么条件下，以什么可观察结果判定通过”。TDD 可以补充实现位置、测试方法和技术证据，但不得降低或改写此处的设计要求。

### 7.1 功能需求清单

| ID | 功能需求 | 需求说明 |
| --- | --- | --- |
| P-01 | 玩家移动与边界 | 观察与瞄准阶段必须允许玩家稳定控制狐狸进行基础方向移动；狐狸不得穿越关卡有效边界。 |
| P-02 | 唯一攻击机会与刀型选择 | 每次关卡尝试只提供一次有效攻击提交机会；按下左键只进入瞄准且不消耗机会，瞄准期右键取消必须返回观察；松开左键时依据狐狸与鼠标距离选择直线斩或弧形斩并正式提交，首次提交后不得再次接受攻击。两种刀型共同消耗同一次攻击机会。 |
| P-03 | 出刀后控制锁定 | 攻击提交时，弧形斩采样狐狸指向鼠标的方向；鼠标在方向死区圆内时短位移为 0，在死区外时按实时箭头方向与边界裁剪后的距离短移。完成采样后必须立即关闭移动、转向、追加攻击、取消及补救输入，后续鼠标或 WASD 输入不得改变本次斩击，直至进入结算。 |
| P-04 | 可观察的敌人行为 | 基础敌人必须执行至少一种连续、可观察且可预测的移动行为；首轮所需运动参数必须可调整。 |
| P-05 | 双刀型命中与死亡 | 远距直线斩按既有直线位移范围判定；近身弧形斩在执行期间持续以狐狸当前位置为圆心进行圆形范围判定，短位移时圆形范围随狐狸移动。瞄准预览与单个时点的圆形判定半径必须一致，跟随刀光必须与执行中的圆形范围同步；任一刀型有效命中的基础敌人均停止行为并死亡。 |
| P-06 | 胜利结算 | 斩击及必要反馈完成后，若所有目标敌人均已死亡，系统必须进入且只进入胜利结算。 |
| P-07 | 失败结算 | 斩击及必要反馈完成后，若仍有任一目标敌人存活，系统必须进入且只进入失败结算。 |
| P-08 | 固定镜头与战场可读性 | 关卡必须使用固定俯视镜头；狐狸、目标敌人、场地边界、主要行动区域、当前刀型及瞄准时的有效斩击范围必须能够被识别。弧形斩瞄准时，攻击圆、方向死区圆与实时位移箭头必须能够区分；执行时，跟随狐狸的圆弧刀光必须能够指示正在生效的圆形范围。 |
| P-09 | 一刀结果反馈 | 系统必须提供可区分的挥刀、命中、敌人死亡及胜败结算反馈；弧形斩必须具有区别于直线斩的狐狸动作和跟随圆弧刀光；表现不得改变命中与胜败真值。 |
| P-10 | 快速重试 | 结算后必须提供明确的重试入口，并将本关恢复为一致、可再次验证的初始状态。 |

### 7.2 验收标准

| ID | 关联需求 | 验收场景与通过条件 |
| --- | --- | --- |
| AC-01 | P-01、P-04、P-08 | 进入基础关卡后，在观察与瞄准阶段均可持续移动狐狸；狐狸不穿越边界，敌人按设定规则和正常时间速度运动。移动鼠标跨过刀型阈值时当前刀型实时更新；弧形斩始终显示以狐狸当前位置为圆心的攻击圆和可调死区圆。鼠标在死区外时显示从圆心指向鼠标的实时箭头，改变角度或靠近边界时箭头方向/长度同步更新；进入死区时箭头隐藏。WASD 不改变箭头方向，主要战场对象在固定镜头中可识别。 |
| AC-02 | P-02、P-03 | 按下左键后进入瞄准，攻击机会保持为 1；右键取消后回到观察，且随后松开左键不得出刀。再次瞄准后，鼠标距离小于阈值时释放只提交一次弧形斩，距离大于等于阈值时释放只提交一次直线斩；攻击机会均由 1 变为 0。弧形斩在死区内提交时原地执行，在死区外提交时只采用狐狸指向鼠标的方向；提交后的鼠标移动、WASD、再次攻击和取消输入均不能改变战斗状态或位移方向。 |
| AC-03 | P-05 | 分别以固定参数重复直线斩与弧形斩：相同初始状态和输入必须产生一致的命中与死亡结果；弧形斩无方向时原地使用圆形范围，有方向时圆形范围随狐狸完成短位移，并能命中执行过程中进入该圆的目标；任一时点处于圆形范围外的目标不得仅因刀光表现被判定命中。 |
| AC-04 | P-06 | 设置能够一次命中全部目标的场景并出刀；斩击及必要反馈完成后仅显示胜利结果，系统不再接受战斗输入。 |
| AC-05 | P-07 | 设置至少保留一个目标存活的场景并出刀；斩击及必要反馈完成后仅显示失败结果，存活目标与失败原因可以被识别。 |
| AC-06 | P-09 | 分别执行全命中、部分命中和无命中的场景；挥刀表现、发生命中时的命中与死亡反馈、以及胜利或失败结算彼此可区分，且不会遮蔽仍存活目标或最终结果。直线斩与弧形斩使用可区分的狐狸动作；弧形斩圆弧刀光在短位移期间持续跟随狐狸，并与圆形判定的中心和半径一致。 |
| AC-07 | P-10 | 从胜利与失败结算各执行一次重试；重试后狐狸与敌人回到设定初始状态，攻击机会恢复为 1，结算界面与上次尝试产生的临时状态被清除。 |
| AC-08 | P-01、P-04、P-05 | 至少准备一个可重复测试的场景，使不同合法站位、时机或刀型产生不同命中结果；同时记录是否存在直线斩等待共线之外的有效选择，用于证明观察与规划能够影响唯一一刀，而非只有装饰意义。 |
| AC-09 | P-01～P-10 | 完整尝试必须按“观察与规划 → 刀型、范围与方向确认 → 一刀结果反馈”的顺序闭合；取消瞄准可返回观察，但不得跳过唯一攻击提交直接结算，也不得在正式出刀后重新返回观察、瞄准或修改已采样的弧形斩位移方向。 |
| AC-10 | 全部 | v0.1 验收构建不得依赖完整关卡组件交互、叙事身份系统、敌人攻击、玩家生命值、额外攻击机会、通用技能系统或成长系统才能完成上述验收。 |

### 7.3 验收记录要求

- 每次正式验收记录 Build 或版本标识、测试日期、关卡或场景、关键参数、初始条件、执行步骤、预期结果、实际结果和结论。
- 功能验收以“通过 / 不通过 / 阻塞”记录；不通过项必须注明对应的 P 与 AC 编号、复现条件和可观察偏差。
- 体验假设不以主观印象替代功能验收。试玩感受记录在附录 A，并注明它支持、削弱或无法判断哪一条 H 假设。
- 参数尚未锁定不构成跳过验收的理由；使用的临时参数必须被记录，使测试结果可以复现。

## 9. 参考作品与设计启发

以下内容只用于比较，不代表项目必须采用对应方案。

| 参考 | 可借鉴 | 需要注意 |
| --- | --- | --- |
| 《武士零》 | 短房间的读局、执行和快速重试 | 不照搬高速操作与高频死亡 |
| 《Into the Breach》 | 信息公开、选择后承担结果、局面可推理 | 本作仍是实时移动与演出导向 |
| 《只狼：影逝二度》 | 处决的仪式感、音画同步与命中确定性 | 本作不能依赖复杂战斗铺垫 |
| 《Undertale》 | 玩法可承载玩家身份与选择的讨论 | 不预设存档、重置或道德结论 |
| 《哈迪斯》《咩咩启示录》 | 俯视空间的读取与构图 | 仍需自行验证固定镜头 |
| 居合、武侠与决斗电影 | 准备过程与瞬间爆发的对比 | 意象不能代替具体机制与角色动机 |

共同启发是“观察与规划—行动决策—不能补救—一刀结果反馈”。主题应从实际测试中的情绪和决策出发，不提前用设定替玩法下结论。

## 10. v0.2 候选功能池

以下不是 v0.2 承诺。只有 v0.1 完成核心验证后，才考虑进入下一版。

| 候选 | 要回答的问题 | 风险 |
| --- | --- | --- |
| 刀型扩展 | v0.1 双刀型实验若成立，是否还需要蓄力、更多形态或更深取舍？ | 增加认知和平衡负担，并可能稀释唯一一刀 |
| 攻击方向 / 范围预览 | 失败是否源于判定不清楚？ | 可能削弱视觉简洁与发现感 |
| 多种敌人 | 预测能否形成组合题？ | 规则过多会迅速增加关卡复杂度 |
| 关卡组件 / 条件调整 | 如何把“利用环境创造出刀条件”转化为清楚、有限且可教学的交互？ | 规则与制作成本可能快速增加 |
| 成长系统 | 长期游戏如何产生变化？ | 可能稀释“唯一一刀” |
| Boss 原型 | 一刀规则如何面对多阶段强敌？ | 容易变成普通动作战斗 |
| 控制关系的叙事表达 | 如何解释玩家为何能够直接控制狐狸，同时保持玩家并非在叙事上直接扮演狐狸？ | 设定不应增加操作理解成本或强迫玩法服务叙事 |
| 关卡元结构 | 章节如何连接？ | 可能过早进入内容制作 |

### A.3 待验证事项汇总

- 首次玩家是否能自然理解“只有一刀、必须全灭、出刀后立即结算”仍未完成独立测试；下一轮至少提供低成本规则提示并记录首次理解，不制作复杂教程。
- “狐狸力竭—存活敌人逼近并终结—时间回溯重试”只作为失败包装与世界观候选，尚未确认，不进入本轮实现。
- 全灭、部分命中和无命中的反馈必须能够区分；全灭时的全屏顿帧、黑白闪等强化表现仍待专项反馈设计与验证，本轮只要求不混淆结果。
- 人工试玩默认关闭敌人路径、关卡状态等调试叠层，必要时仅在开发验收中开启，避免 UI 噪音影响体验判断。
- DQ-001 继续保持待验证：本轮结果只否定“增加敌人运动混乱即可产生主动性”，不能直接触发大规模反 ARPG 重构。
