## 1. 游戏定位与核心体验

### 1.1 一句话概念 [已确认]

一个只能挥出一刀的狐狸骑士，通过观察战场、规划行动与调整自身位置，在不可逆的攻击中决定战斗结果。

v0.1 以最小形式验证这一概念：玩家在清楚可读的俯视战场中直接控制狐狸移动和站位，选择唯一一次出刀；刀落之后，战斗控制结束，系统自动演算并结算结果。

### 1.2 类型与核心反转 [已确认]

- 游戏类型为 2D 动作解谜游戏，结合动作游戏的打击反馈、解谜游戏的观察与推理，以及战术游戏的行动规划。
- 核心反转是弱化传统动作游戏的连续攻击与持续输出，强调理解世界、规划行动，并通过一次不可逆的攻击改变结果。
- “反传统 ARPG”是项目方向，不代表 v0.1 需要建立完整 ARPG 系统后再进行反转。

### 1.3 设计支柱

| 支柱 | 玩家感受 | v0.1 设计含义 |
| --- | --- | --- |
| 一次攻击，改变结果 | 攻击是决定，而不是循环消耗 | 唯一攻击；没有普通攻击；出刀后不能补救 |
| 观察胜过操作 | 理解规律、环境与解法比反应速度或连招更重要 | 敌人行为与战场信息清楚；操作门槛较低 |
| 理解与准备带来爆发 | 通过观察世界、调整条件，创造决定性的攻击机会 | 以移动和站位承担最小准备过程；一刀提供强烈的视觉与情绪反馈 |
| 每一次行动都有重量 | 移动、交互和攻击都可能影响最终结果 | v0.1 先验证移动、站位、时机与唯一一刀；完整关卡交互暂不实现 |

核心体验链路为：

> 观察与规划 → 行动决策 → 一刀结果反馈

### 1.4 核心体验假设 [待验证]

- H1：唯一一次攻击机会能够产生有趣的站位与时机决策。
- H2：若前置信息足够清楚，出刀后失去控制会让玩家感到“确认选择并见证结果”，而不是“被剥夺操作”。
- H3：高质量的斩击反馈能够让玩家此前的理解与准备获得明确的视觉、听觉和情绪回报。
- H4：理解局面并用一次选择改变结果，可能成为长期方向；v0.1 只验证最基础的玩法形式，不确定最终主题。
- H5：在仍然只有一次攻击机会的前提下，以鼠标距离选择远距直线斩或近身弧形斩，能够增加空间表达与主动决策，而不会把“一刀”削弱为多技能循环或硬解谜的答案提交。

## 2. v0.1 原型验证目标

- 玩家能否迅速理解：可以移动、只有一刀、需要尽量一次解决所有敌人？
- 移动敌人是否让站位从静态找答案变为观察、预测与调整？
- 出刀后失去控制是否自然、清楚且令人期待？
- 斩击反馈是否足以回报此前的观察、规划与行动准备？
- 失败后玩家能否理解问题所在，并愿意立即重试？
- 更主观的感受：这个 Demo 是否好玩？是否具有可延展性？
- 两种可预览刀型能否减少“只能等待敌人共线”的单一解法，并把主动性集中在如何塑造和提交唯一一刀上？

v0.1 不验证完整世界观、商业定位、长期成长、关卡编排、Boss 战或重复游玩结构，也不追求高难反应、格挡和连招深度。具体不做的系统见第 8 节。

## 3. 核心玩法流程

### 3.1 玩家流程 [已确认]

| 阶段 | 玩家权限 | 系统行为 | 退出条件 |
| --- | --- | --- | --- |
| 进入关卡 | 无 / 短暂锁定 | 生成狐狸与敌人，显示主要战场信息 | 初始化完成 |
| 观察、规划与站位 | 移动、观察、调整位置、选择时机 | 敌人按简单规则移动 | 玩家按下鼠标左键进入瞄准 |
| 瞄准与调整 [待验证] | 保持移动；移动鼠标调整距离与方向；右键取消 | 根据狐狸到鼠标的距离实时选择并显示与有效判定一致的直线斩或弧形斩范围；敌人保持正常移动 | 松开左键提交，或右键取消 |
| 确认出刀 | 不再接受战斗输入 | 消耗唯一一刀；锁定提交时的刀型与范围，随后关闭战斗输入 | 攻击启动 |
| 自动演算 | 无控制权 | 完成斩击、命中、死亡和反馈 | 表现完成 |
| 结算 | 无战斗控制 | 统计目标敌人 | 0 个存活为胜利，否则失败 |
| 重试 / 离开 | 菜单输入 | 重置本关或退出 | 玩家选择 |

松开鼠标左键是 v0.1 刀型实验的攻击提交点。提交前可以移动和右键取消，且不消耗攻击机会；提交时根据鼠标距离确定刀型。近身弧形斩固定为以狐狸提交位置为圆心的原地 360 度斩击，远距直线斩继续沿鼠标方向位移。提交后玩家不能继续移动、转向、追加输入、取消或补救。未来是否允许执行期持续互动仍是未决问题，不属于 v0.1。

### 3.2 目标节奏 [待验证]

进入与读图（1–3 秒）→移动、观察与规划（5–20 秒）→一刀爆发（约 0.5–2 秒）→清楚结算（1–3 秒）→立即重试。中间阶段的具体情绪尚未定义；具体时长需要调试，不是锁定参数。

## 4. 系统规格

### 4.1 玩家角色与移动 [已确认]

- 使用可移动的狐狸骑士白模或占位表现。
- 采用 2D 俯视视角，移动平面与碰撞边界清楚。
- 提供基础方向移动，速度可调；不要求冲刺、翻滚、格挡或连击。
- 移动用于调整站位、改变斩击覆盖关系，并观察敌人是否形成合适位置。

操作层面，玩家在 v0.1 直接控制狐狸，这与叙事身份并不冲突。叙事层面已确认玩家并非直接扮演狐狸骑士；这种控制可能来自尚未确定的能力、身份或规则关系。v0.1 不解释该关系，也不建立叙事身份系统。

### 4.2 唯一一刀与双刀型实验 [已确认 / 待验证]

- 每次关卡尝试只能攻击一次，没有普通攻击。
- v0.1 刀型实验仍只消耗唯一一次攻击，但根据提交时狐狸与鼠标的距离选择两种临时斩击形态。该实验用于验证一刀内部的空间表达能否增加主动性，不代表正式技能系统或最终斩击形态。
- 弧形斩半径同时承担刀型切换距离，不再另设可调刀型阈值：狐狸与鼠标的距离小于弧形斩有效半径时选择近身弧形斩；距离大于等于该半径时选择既有远距直线位移斩。直线斩的方向、直线覆盖、边界截断和移动逻辑保持原实验规则。
- 近身弧形斩固定为以狐狸提交位置为圆心的 360 度原地斩击；执行期间狐狸不发生位移，圆形有效范围、圆弧刀光和狐狸动作保持同心。弧形斩不再具有短位移、方向死区或位移箭头。
- 弧形斩的瞄准指示只显示以狐狸当前位置为圆心、半径等于真实有效判定半径的暖橙攻击圆。该攻击圆边缘本身就是切换到远距直线斩的边界，不另叠第二个外圈。
- 当前为远距直线斩时，除冷青直线攻击框外，保留一个以狐狸为圆心、半径等于弧形斩有效半径的低亮度暖橙无填充圆，用于提示“鼠标回到圈内将切换为弧斩”。该圈只通过低强度透明度呼吸，不改变半径、线宽或填充；它不是第二层攻击范围。鼠标或狐狸移动导致刀型跨界时，边界圆必须产生一次明显强于呼吸的短促 UI 光效，并播放一次轻微切换音效；停留在同一刀型时不得重复触发。
- 两种刀型必须使用不同且一致的视觉语言：近身弧形斩使用暖橙／金色，远距直线斩使用冷青／蓝白色；差异至少覆盖瞄准范围、方向线与执行刀光，使玩家能够在松开前确认当前刀型。颜色只表达刀型，不改变命中与胜败真值。
- 弧形斩必须使用区别于远距直线斩的狐狸动作和圆弧形刀光。角色动作、刀光与圆形命中范围需要在同一执行时段内同步，且表现不得扩大或缩小真实命中集合。
- 弧形斩基础半径必须作为 Prototype 可调参数开放；刀型切换距离直接使用应用命中宽容度后的弧形斩有效半径，不单独开放参数。默认值只作为测试起点，不是锁定设计。
- 基础小怪被有效命中后死亡。
- 出刀后玩家立即失去战斗控制。
- 系统完成斩击、命中、死亡和胜败结算。
- 重开关卡后恢复一次攻击机会。

- [待验证] v0.1 使用“按住鼠标左键瞄准、松开提交、瞄准时右键取消”的临时输入方案。瞄准期不锁定移动，不启用时间缩放；鼠标距离决定刀型，直线斩方向由狐狸指向鼠标，弧形斩不需要方向。WASD 只负责瞄准期移动狐狸。
- [待验证] 鼠标与狐狸重合时仍属于近身弧形斩，并明确提交为原地弧形斩，不因缺少方向而自动取消。

两种刀型都对基础小怪保持一击必杀，且共同消耗同一把唯一一刀。斩击的最终形状、移动方式、瞄准方法和输入方法仍未最终确定；上述方案只用于 v0.1 低成本验证主动性、操作清晰度与仪式感。v0.1 不建立支持多技能的通用框架，只保留这两种临时几何及其少量可调参数。

### 4.3 敌人 [已确认]

- 具备至少一种简单、可观察的移动行为。
- 初始位置、移动速度、移动方向或路径可调。
- 被有效命中后停止行为并死亡。
- 不主动攻击狐狸；不实现玩家生命值、狐狸受伤或死亡。
- 不实现护甲、技能、群体协作、元素反应等复杂状态。

移动方式可从固定方向、往返巡逻或趋近中选择一种，不要求同时支持全部类型。

### 4.4 镜头

- [已确认] 使用固定俯视相机，不常规跟随狐狸。
- [已确认] 不实现自由缩放、手动平移或常规跟随。
- [待验证] 是否需要完整、无裁切地显示整个关卡，需结合屏幕比例与可读性测试。
- [待验证] 斩击瞬间可测试短促震屏，但不能妨碍读取命中和存活信息。

镜头目标是让玩家尽可能清楚地理解主要战场信息。

### 4.5 胜败与重试 [已确认]

- 自动演算结束时，所有目标敌人死亡则胜利。
- 自动演算结束时，仍有目标敌人存活则失败。
- 结算需要清楚显示结果，并提供快速重试。

失败在世界观中的解释、狐狸是否会死亡均不属于已确认规格，见 OQ-06 与 OQ-12。

### 4.6 反馈与演出

| 层级 | 最低要求 [已确认] | 增强方向 [待验证] |
| --- | --- | --- |
| 预备 | 可攻击状态、朝向、刀型切换边界与当前刀型清楚；跨过边界时有短促光效和轻微音效 | 轻微蓄势姿态或进一步音效区分 |
| 命中 | 受击与死亡状态清楚 | 命中停顿、残影或斩线 |

| 声音 | 挥刀、命中、结算三类反馈 | 环境收束、刀鸣与余响 |

## 5. 关卡与内容规格

### 5.1 首轮基础关卡 [已确认]

- 首轮只要求完成一个可重复开始的基础敌人关卡。
- 使用单场景、单房间和固定相机。
- 至少有一个狐狸出生点及多个可配置的敌人出生点。
- 边界或障碍只需满足移动与站位测试，不制作完整机关系统。
- 敌人移动应尽量不依赖文字教程也能理解。
- 狐狸移速、敌人位置与移动参数、临时斩击判定和基础反馈可调。

### 5.2 关卡原则 [待验证]

- 问题主要来自空间和时间关系，而不是高精度输入。
- 玩家在出刀前应获得足够信息；失败应更接近“我判断错了”，而不是“系统隐藏了规则”。
- 理想解应呈现一次干净、整体性的解决。
- 长期方向允许玩家通过移动、刀型、关卡组件或环境因素调整条件并创造出刀机会；v0.1 本轮先以移动、站位、敌人运动和两种可预览刀型验证这一原则，不制作完整关卡交互系统。关卡交互不得为了增加主动性而退化成固定站位、固定机关顺序或唯一答案的硬解谜；是否加入仍待后续单独验证。
- 基础关卡完成后，可复制 3–5 个少量参数变体用于比较；这些变体不是首轮验收要求。

### 5.3 视觉与主题方向

- [已确认] 视觉方向关键词：暗黑幻想、像素风格、俯视角。
- [已确认] 主题探索关键词：选择、后果、命运、道德困境、反传统 ARPG 体验。
- [待验证] v0.1 的美术首先服务于角色、敌人、边界、斩击与结果的可读性；不要求以正式美术资源验证最终风格完成度。
- [未决] 主题关键词如何进入具体剧情、关卡选择与“一刀”的意义，仍需后续设计，不由关键词直接推导世界观结论。

## 6. 信息、界面与可用性

- HUD 最低信息包括剩余攻击次数（1/0）、目标敌人状态和胜败结算。
- [待验证] 进入瞄准状态后必须显示当前将提交的刀型及其有效范围：远距直线斩显示方向、宽度与终点；近身弧形斩只显示以狐狸当前位置为圆心、半径等于真实有效判定半径的暖橙攻击圆。弧斩攻击圆边缘同时是刀型切换边界，弧斩状态不得再叠第二个外圈；远直状态保留同半径、低亮度、无填充的暖橙圆，提示鼠标回到圈内会切为弧斩。该提示圈呼吸只改变透明度，跨界时才触发一次更强的目标刀型颜色光效与轻微音效。狐狸或鼠标改变相对距离时预览必须实时更新；弧形斩使用暖橙／金色，直线斩使用冷青／蓝白色，瞄准与执行保持一致；弧形斩提交后的圆形刀光与狐狸保持原地同心。
- 敌人、狐狸、斩击轨迹和场地边界需要有足够对比。
- 震屏与闪光应可调，不能妨碍读取信息。
- 教程优先使用行动提示和首关构图，v0.1 不制作大量文字说明。

## 7. v0.1 功能需求与验收标准

只提供支持快速迭代的必要参数：狐狸移动速度；敌人初始位置、速度及移动方向或路径；直线斩距离与宽度；弧形斩半径；基础反馈强度与时点；结算等待时间和关卡重置。刀型切换距离由弧形斩有效半径派生，不作为独立参数。

本节是 GDD 交付给 TDD 的需求基线。功能需求说明“系统必须具备什么行为”，验收标准说明“在什么条件下，以什么可观察结果判定通过”。TDD 可以补充实现位置、测试方法和技术证据，但不得降低或改写此处的设计要求。

### 7.1 功能需求清单

| ID | 功能需求 | 需求说明 |
| --- | --- | --- |
| P-01 | 玩家移动与边界 | 观察与瞄准阶段必须允许玩家稳定控制狐狸进行基础方向移动；狐狸不得穿越关卡有效边界。 |
| P-02 | 唯一攻击机会与刀型选择 | 每次关卡尝试只提供一次有效攻击提交机会；按下左键只进入瞄准且不消耗机会，瞄准期右键取消必须返回观察；松开左键时，狐狸与鼠标距离小于弧斩有效半径则提交原地弧形斩，距离大于等于该半径则提交直线斩；首次提交后不得再次接受攻击。两种刀型共同消耗同一次攻击机会。 |
| P-03 | 出刀后控制锁定 | 攻击提交时必须立即固定当前刀型、有效范围及直线斩方向，并关闭移动、转向、追加攻击、取消及补救输入。弧形斩必须以提交位置原地执行；后续鼠标或 WASD 输入不得改变本次斩击，直至进入结算。 |
| P-04 | 可观察的敌人行为 | 基础敌人必须执行至少一种连续、可观察且可预测的移动行为；首轮所需运动参数必须可调整。 |
| P-05 | 双刀型命中与死亡 | 远距直线斩按既有直线位移范围判定；近身弧形斩在执行期间持续以狐狸提交位置为圆心进行圆形范围判定，狐狸不发生位移。刀型切换边界、瞄准预览、圆形判定与圆弧刀光必须使用同一有效半径；任一刀型有效命中的基础敌人均停止行为并死亡。 |
| P-06 | 胜利结算 | 斩击及必要反馈完成后，若所有目标敌人均已死亡，系统必须进入且只进入胜利结算。 |
| P-07 | 失败结算 | 斩击及必要反馈完成后，若仍有任一目标敌人存活，系统必须进入且只进入失败结算。 |
| P-08 | 固定镜头与战场可读性 | 关卡必须使用固定俯视镜头；狐狸、目标敌人、场地边界、主要行动区域、当前刀型及瞄准时的有效斩击范围必须能够被识别。弧形斩状态只显示一个暖橙攻击圆，其边缘同时作为刀型切换边界；不得再显示方向死区、位移箭头或第二个外圈。直线斩状态在冷青攻击框之外，显示一个同弧斩有效半径、低亮度、无填充且仅以透明度呼吸的暖橙提示圈；每次实际跨界提供一次明显更强的目标刀型颜色光效和轻微音效，同侧刷新不得重复触发。执行时，圆弧刀光必须与原地狐狸及真实圆形范围同心。 |
| P-09 | 一刀结果反馈 | 系统必须提供可区分的挥刀、命中、敌人死亡及胜败结算反馈；近身弧形斩以暖橙／金色预览与圆弧刀光表达，远距直线斩以冷青／蓝白色预览与直线刀光表达；弧形斩还必须具有区别于直线斩的狐狸动作和原地同心圆弧刀光。表现不得改变命中与胜败真值。 |
| P-10 | 快速重试 | 结算后必须提供明确的重试入口，并将本关恢复为一致、可再次验证的初始状态。 |

### 7.2 验收标准

| ID | 关联需求 | 验收场景与通过条件 |
| --- | --- | --- |
| AC-01 | P-01、P-04、P-08 | 进入基础关卡后，在观察与瞄准阶段均可持续移动狐狸；狐狸不穿越边界，敌人按设定规则和正常时间速度运动。弧斩状态只显示一个暖橙攻击圆，其边缘等于真实刀型边界；直斩状态显示冷青攻击框和一个低亮度暖橙弧斩区提示圈。提示圈呼吸期间只有透明度变化，半径、缩放和线宽保持不变。移动鼠标或狐狸跨过圆边缘时当前刀型实时更新，每次跨界只触发一次明显强于呼吸的短促圈层光效和轻微音效，停留于同一侧时不重复触发。弧斩状态不得显示第二个外圈、方向死区或位移箭头，主要战场对象在固定镜头中可识别。 |
| AC-02 | P-02、P-03 | 按下左键后进入瞄准，攻击机会保持为 1；右键取消后回到观察，且随后松开左键不得出刀。再次瞄准后，鼠标距离小于弧斩有效半径时释放只提交一次原地弧形斩，距离大于等于该半径时释放只提交一次直线斩；攻击机会均由 1 变为 0。弧形斩从开始到结束狐狸位置保持不变；提交后的鼠标移动、WASD、再次攻击和取消输入均不能改变战斗状态、刀型或有效范围。 |
| AC-03 | P-05 | 分别以固定参数重复直线斩与原地弧形斩：相同初始状态和输入必须产生一致的命中与死亡结果；弧斩刀型边界、预览、判定与刀光使用同一有效半径，圆内目标被命中，圆外目标不得仅因刀光表现被判定命中；命中宽容度只应用一次。 |
| AC-04 | P-06 | 设置能够一次命中全部目标的场景并出刀；斩击及必要反馈完成后仅显示胜利结果，系统不再接受战斗输入。 |
| AC-05 | P-07 | 设置至少保留一个目标存活的场景并出刀；斩击及必要反馈完成后仅显示失败结果，存活目标与失败原因可以被识别。 |
| AC-06 | P-09 | 分别执行全命中、部分命中和无命中的场景；挥刀表现、发生命中时的命中与死亡反馈、以及胜利或失败结算彼此可区分，且不会遮蔽仍存活目标或最终结果。直线斩的冷青／蓝白色预览与刀光、弧形斩的暖橙／金色预览与刀光能够区分，且各自从瞄准保持到执行；两者使用可区分的狐狸动作，弧形斩圆弧刀光在原地执行期间与狐狸和圆形判定的中心、半径一致。 |
| AC-07 | P-10 | 从胜利与失败结算各执行一次重试；重试后狐狸与敌人回到设定初始状态，攻击机会恢复为 1，结算界面与上次尝试产生的临时状态被清除。 |
| AC-08 | P-01、P-04、P-05 | 至少准备一个可重复测试的场景，使不同合法站位、时机或刀型产生不同命中结果；同时记录是否存在直线斩等待共线之外的有效选择，用于证明观察与规划能够影响唯一一刀，而非只有装饰意义。 |
| AC-09 | P-01～P-10 | 完整尝试必须按“观察与规划 → 刀型与范围确认 → 一刀结果反馈”的顺序闭合；取消瞄准可返回观察，但不得跳过唯一攻击提交直接结算，也不得在正式出刀后重新返回观察、瞄准或修改已提交的刀型与范围。 |
| AC-10 | 全部 | v0.1 验收构建不得依赖完整关卡组件交互、叙事身份系统、敌人攻击、玩家生命值、额外攻击机会、通用技能系统或成长系统才能完成上述验收。 |

### 7.3 验收记录要求

- 每次正式验收记录 Build 或版本标识、测试日期、关卡或场景、关键参数、初始条件、执行步骤、预期结果、实际结果和结论。
- 功能验收以“通过 / 不通过 / 阻塞”记录；不通过项必须注明对应的 P 与 AC 编号、复现条件和可观察偏差。
- 体验假设不以主观印象替代功能验收。试玩感受记录在与当前 GDD 版本绑定的 [`Prototype Test Log`](playtest/PrototypeTestLog_v0.1.md)，并注明它支持、削弱或无法判断哪一条 H 假设。
- 参数尚未锁定不构成跳过验收的理由；使用的临时参数必须被记录，使测试结果可以复现。

## 9. 参考作品与设计启发

以下内容只用于比较，不代表项目必须采用对应方案。

| 参考 | 可借鉴 | 需要注意 |
| --- | --- | --- |
| 《武士零》 | 短房间的读局、执行和快速重试 | 不照搬高速操作与高频死亡 |
| 《Into the Breach》 | 信息公开、选择后承担结果、局面可推理 | 本作仍是实时移动与演出导向 |
| 《只狼：影逝二度》 | 处决的仪式感、音画同步与命中确定性 | 本作不能依赖复杂战斗铺垫 |
| 《Undertale》 | 玩法可承载玩家身份与选择的讨论 | 不预设存档、重置或道德结论 |
| 《哈迪斯》《咩咩启示录》 | 俯视空间的读取与构图 | 仍需自行验证固定镜头 |
| 居合、武侠与决斗电影 | 准备过程与瞬间爆发的对比 | 意象不能代替具体机制与角色动机 |

共同启发是“观察与规划—行动决策—不能补救—一刀结果反馈”。主题应从实际测试中的情绪和决策出发，不提前用设定替玩法下结论。

## 10. v0.2 候选功能池

以下不是 v0.2 承诺。只有 v0.1 完成核心验证后，才考虑进入下一版。

| 候选 | 要回答的问题 | 风险 |
| --- | --- | --- |
| 刀型扩展 | v0.1 双刀型实验若成立，是否还需要蓄力、更多形态或更深取舍？ | 增加认知和平衡负担，并可能稀释唯一一刀 |
| 攻击方向 / 范围预览 | 失败是否源于判定不清楚？ | 可能削弱视觉简洁与发现感 |
| 多种敌人 | 预测能否形成组合题？ | 规则过多会迅速增加关卡复杂度 |
| 关卡组件 / 条件调整 | 如何把“利用环境创造出刀条件”转化为清楚、有限且可教学的交互？ | 规则与制作成本可能快速增加 |
| 成长系统 | 长期游戏如何产生变化？ | 可能稀释“唯一一刀” |
| Boss 原型 | 一刀规则如何面对多阶段强敌？ | 容易变成普通动作战斗 |
| 控制关系的叙事表达 | 如何解释玩家为何能够直接控制狐狸，同时保持玩家并非在叙事上直接扮演狐狸？ | 设定不应增加操作理解成本或强迫玩法服务叙事 |
| 关卡元结构 | 章节如何连接？ | 可能过早进入内容制作 |

## 14. v0.1 阶段结算草案 [待确认]

### 14.1 核心假设阶段结果

| 假设 | 阶段结果 | 依据与边界 |
| --- | --- | --- |
| H1：唯一一次攻击产生有趣的站位与时机决策 | 暂未成立 | 当前基础组合能够产生可预测的站位和时机窗口，但主要行为仍可退化为识别中心或共线位置后等待；创作者明确认为当前白模不好玩，不能用功能可完成代替“有趣”成立 |
| H2：出刀后失去控制像确认选择而非被剥夺 | 尚无法判断 | 当前只有“提交斩击—直接检查是否全灭”的短链路，玩家出刀时通常已知道结果；尚无斩击与敌人状态或环境继续交互的自动演算过程，因此不足以验证见证后果的体验 |
| H3：斩击反馈足以回报此前准备 | 暂未成立 | 刀型、范围、命中和胜败已能识别，但当前占位表现没有形成足以抵偿等待的兴奋、仪式感或重试动力 |
| H4：理解局面并用一次选择改变结果可成为长期方向 | 尚无法判断 | v0.1 只证明最小操作与结果链路可以运行；长期方向仍依赖更丰富但可读的敌人、关卡条件和内容结构验证 |
| H5：双刀型增加空间表达与主动决策，且不退化为硬解谜 | 部分成立 | 原地弧斩和直线位移斩可以预判、定位清楚，并在四敌人测试板中形成彼此不可替代的空间解；但该板子的主要思路仍是“识别中心点—等待窗口—交答案”，没有证明主动塑造局面成立 |
